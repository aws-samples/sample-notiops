# AWS What's New 报告（针对指定时间窗）

当用户要求"查看某个时段的 AWS 新发布/更新"、"这段时间 AWS 有哪些新功能"，或"给我一份 What's New 列表/报告"时，运行本技能。

## 步骤 1 —— 确认时间窗
- 解析时间窗；**基于当前日期**（每轮都会注入今天的日期）将相对表述（"上个月""过去一个月""本月""过去两周"）转换为绝对的起止日期（YYYY-MM-DD）。
- 用户也可能指定某个**服务**（例如"只看 EC2/S3"）或某个**关键词**——将其作为过滤条件。
- 若未给出时间窗 → 默认取最近 30 天，并说明可以指定范围。

## 步骤 2 —— 拉取数据并按条目数量分支

首先使用 **`aws_whats_new`** 工具拉取该时间窗（及可选的服务/关键词过滤）的发布列表。**根据条目数量决定输出形式：**

### 情况 A —— 20 条或以内
直接在对话中以列表形式呈现；每条包含：
- **标题**（用官方链接包裹，可点击）
- **日期**
- **涉及的服务**
- 一行摘要

### 情况 B —— 超过 20 条
你**必须**改用 **`aws_whats_new_report`** 工具（它会将完整列表渲染为 markdown、保存到 S3 并返回下载链接——不要把长列表塞进对话）：
- 该工具会将**完整列表**以 **markdown 表格**形式保存到 S3，并返回下载链接。
- 在对话中只呈现**前约 20 条作为预览** + 说明"共 N 条，完整列表见下载链接"。
- **不要自己把下载 URL 粘贴进回复**——系统会在末尾自动附加。
- **不要**手动把数十条内容打印到对话中（会超出输出上限并浪费 token）。

> 经验法则：只要总条目数 > 20，就走情况 B（`aws_whats_new_report` → S3 + 下载链接），无论用户是否明确要求"报告/下载"。这是本技能的核心约定。

## 步骤 3 —— 覆盖完整性
- 如果数据源未覆盖整个时间窗（feed 未回溯到时间窗的起点），**如实说明**（"较早的条目可能不完整"），并主动提出可通过网络搜索查找更早的发布。
- 切勿编造发布条目或链接——所有条目都必须来自工具的官方数据。

## 输出风格
- 结论先行："从 <start> 到 <end>，AWS 共有 N 条新发布"，然后是列表/预览。
- 使用表格；标题可点击；日期清晰。
- 使用用户的语言回复（中文用户用中文，其余用英文）；摘要可保留官方英文标题。
