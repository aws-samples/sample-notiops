**先选入口** —— 同一件事两边往往都能做,但擅长的场景不同:

| 你要做的事 | 用哪个 | 为什么 |
|---|---|---|
| 坐下来专注排查一次故障,边看分析过程边等结论 | **Web Chat** | 右侧有实时「思考过程」面板,长报告可在线读、可下载 |
| 做成本复盘 / 看安全态势 / 走 Support 建案全流程 | **Web Chat** | 这些主题带仪表盘和结构化卡片,只有 Web 端有 |
| 写 / 管理 / 发布自建 Skills | **只有 Web Chat** | skill 相关意图已于 2026-09-06 从 IM 侧整体退役(见 §5) |
| 值班时想在群里就地问一句、顺手拉上同事 | **IM bot** | 在群里 @ 一下就能问、能派深度调查,回答和报告全组可见(注意:本版本告警**不会**自动推进 IM 群,告警在 Web 的「通知」里看,见 §14)|
| 手机上快速问一句,@ 一下就走 | **IM bot** | 不用开电脑 |

> 两个入口**默认只读**,唯一的写是 **AWS Support case**(建案 / 回复 / 关闭),而且要你确认之后才执行(§1.5、§12)。只读是**各自**保证的 —— Web Chat 靠「IAM 权限(硬边界,对你的基础设施只读)+ 工具层只读 + 命令级 denylist + 只读 system prompt」;IM 端默认的 DevOps Agent 直连靠「DevOps Agent 侧的只读 agent + 只读角色」,切到 `/agent notiops` 之后则由 Web Chat 那同一个 AgentCore Runtime 用它的只读角色和只读工具来答(同 §8.1);两条路上 NotiOps 侧都再加一条变更措辞正则。详见 §8 与 §9 的「这个『只读』是谁保证的」。任何会变更 AWS 环境的动作,两边都只出预览等你确认,或者直接让你去对应控制台完成。

# 第一部分 · Web Chat 网页控制台(主入口)

> 这一部分是 NotiOps 的主线。你在浏览器里登录一次,就能用自然语言完成故障调查、成本复盘、安全态势查看、AWS Support 建案、AWS 新发布跟踪、自建 Skills 调用,以及告警通知的集中查看。

## 1. 5 分钟上手:第一次打开 Web Chat

Web Chat 是 NotiOps 的网页控制台:一个浏览器页面,左边是导航,中间是对话,右边按需弹出「来源」和「思考过程」。你在里面用自然语言提问,它用**只读**权限去看你的 AWS 环境,然后把结论、证据和链接一起给你。

### 1.1 登录

管理员会给你一个网址和一个初始账号。

1. 打开网址,看到一张登录卡片:标题 **Sign in to NotiOps**,两个输入框(Username / Password),一个 **Sign in** 按钮。登录成功前,页面上不会出现任何对话界面。
2. **首次登录一定会被强制改密**:同一张卡片接着要求你 **Set a new password**,设完直接进入。
3. **部署要求两步验证时**(「强制」档,见 [§1.6](#16-两步验证验证器-app)),改完密码紧接着要你绑定验证器:用验证器 App 扫卡片上的二维码,输入它显示的 6 位验证码。之后每次登录,密码之后都多一步 **Two-step verification**:输入 6 位验证码。
4. 登录页刻意**只有英文**,页面上没有语言开关 —— 中文界面在登录之后切。登录失败时显示 Cognito 给的原因(英文);遇到这一页不支持的验证步骤会显示 `This sign-in step is not supported here: <步骤名>`。
5. **忘记密码**:点登录卡片上的 **Forgot password?**,验证码发到你账号上已验证的邮箱;没有邮箱的请管理员重置。详见 [§1.7](#17-忘记密码与账户设置)。

**初始用户名两条部署路径都是 `admin`**,临时密码取法不同:

- **一键部署(方式 A)**:按 CloudFormation Outputs 里的提示,到你填的那个邮箱收。
- **完整部署(方式 B,`setup.sh`)**:临时密码直接打印在部署终端里。

> 登录用的是 NotiOps 的 Cognito 用户池(和主动通知那套是同一个部署)。**没有自助注册** —— 需要新账号找管理员。**忘记密码可以自己找回**(前提是账号绑定了已验证的邮箱),没有邮箱的找管理员重置,见 [§1.7](#17-忘记密码与账户设置)。

### 1.2 先把语言和外观调成你习惯的

**点左下角你自己的名字**,弹出用户菜单。菜单里是四项(部署开着两步验证时多一项 **两步验证**,见 [§1.6](#16-两步验证验证器-app)),前两项值得第一次就设好:

| 菜单项 | 说明 |
|---|---|
| **外观 / Appearance** | 只有 **深色 / Dark**(默认)和 **浅色 / Light**,没有「跟随系统」 |
| **语言 / Language** | 只有两个选项:`English (United States)` 和 `中文（简体）`。**新浏览器默认是英文**,选一次就记在这台浏览器上 |
| **账户与密码 / Account & password** | 邮箱(忘记密码时收验证码)、修改密码、退出所有设备,见 [§1.7](#17-忘记密码与账户设置)。没绑邮箱时,头像和这一项上有个橙色小点 |
| **两步验证 / Two-step verification** | 只有部署开着两步验证时才有:开启 / 换一个验证器 / 关闭,见 [§1.6](#16-两步验证验证器-app) |
| **退出登录 / Sign out** | 退回登录卡片 |

你名字右边那个 GitHub 图标(悬停时提示「在 GitHub 给 NotiOps 加星」)在新标签页打开公开仓库首页 —— 更新日志(Releases)和提问题(Issues)都从那里进。2026-09-12 起菜单里原来那三条外链(更新日志 / 了解更多 / 反馈问题)已经下线。

> ⚠️ **2026-09-11 起菜单里没有「设置」这一项了**。它从来没实现,点了只弹一个「设置 · 即将上线」提示框 —— 整项下线,不再占位。真正的配置入口在侧栏 **更多 → 管理**(角色 / 权限 / 模型 / IM 凭据)和 **更多 → 巡检 → 配置**(巡检范围 / 阈值与定时),跟这里不是一回事。

> 界面语言只影响 **UI 文案**。回答用什么语言,由你**提问用的语言**决定 —— 中文问就中文答。

### 1.3 界面三块

- **左侧导航**:最上面是 **新对话**,下面是 4 个一级入口(通知 / 调查 / 成本 / 案例)和一个可展开的 **更多**(巡检 / 技能 / 定时任务 / 管理 —— 各自显不显示仍看权限、部署方式和「模块」开关;当前页就在其中时会自动展开,展开 / 收起会被记住;三项都不显示时「更多」整个不出现,原因见 §2.10),再下面是你的**会话列表**(按主题分组),最下面是一张 **What's New** 卡片和你的用户菜单。侧边栏本身可以收起(「收起侧边栏」/「展开侧边栏」)。
- **中间对话区**:顶栏显示会话标题、主题标签和**账号选择器**;中间是消息;底部是输入框和它的工具栏。
- **右侧停靠面板**:平时不占地方。需要时会滑出 **Sources**(这次回答用了哪些出处)或**思考过程**(它一步步做了什么)。两个面板共用同一条右侧轨道,一次只显示一个。

### 1.4 问出第一句话

点 **新对话**,你会看到:一个会呼吸的 logo、一句标题「在 NotiOps 里想做点什么?」、一个**对话对象选择器**,以及 **4 张起手卡片**。

起手卡片是从 12 句里**随机抽 4 张**,每开一个新对话重抽一次。点一张卡片,它把那句话**填进输入框**(不会直接发送、也不会切换主题),你可以改完再发。

回车发送,`Shift + 回车` 换行。输入框下面永远有一行提醒:「NotiOps 可能出错,重要结论请核实」。

**对话对象:这一整个会话由谁来答**(只有**通用会话**有这个选择器,进具体主题后不出现):

| 选项 | 界面上的原话 | 意味着什么 |
|---|---|---|
| **NotiOps** | 全局视角 · 巡检、调查、案例与知识库 | 走我们编排的模型 + 只读工具集,能建案、能查巡检、能用知识库 |
| **AWS DevOps Agent** | 深入现场 · 实时排查,免模型配置 | 直连你自己的 AWS DevOps Agent,**0 token**(用量计在你的 DevOps Agent 上) |

- 二选一,默认 **NotiOps**,也可以直接打字跳过不选。
- 段名里那个 **AWS** 是刻意的:这一排定的是「这句话交给谁答」,而两条路的答话方、可用工具、用量记在谁头上全都不同,所以段名必须自己点明。
- 这是个**两阶段控件**:第一条消息发出去之前可以随便切,**发出第一句之后就锁定**,想换请新开一个会话。刷新页面或换台设备打开同一个会话,对象还是原来那个。
- 「**免模型配置**」不只是省 token:一个还没在 Bedrock 开通任何模型的新部署,选这一边(或在主题里打开「深度调查」开关)就能**直接发送** —— 发送按钮会绕过模型目录门禁。
- **没配好就只有那一段是置灰的,而且原因会写在控件下面那行提示里**(不是只有鼠标悬停才看得到):这个账号没接入 DevOps Agent 时灰的就是右边那段,提示会说清是「这个账号还没接入」还是「本部署侧没接入」。如果你之前选中的正是被置灰的那一段,它会**自动退回** NotiOps —— 置灰之后你自己点不回来。
- 选了 DevOps Agent 之后,输入框会去掉联网搜索和模型选择器,但**「/」命令按钮还在、而且真的有用**(§5.6)。
- 会话标题栏上的 **NotiOps / AWS DevOps Agent** 标签就是当前对象(与上面那一排段名**逐字一致**,也与回答页脚的署名一致);历史还在水合时这个标签刻意不渲染,别把「暂时没有标签」当成 NotiOps。

### 1.5 第一次就该知道的三件事

1. **它对你的基础设施只读**。它能看你的 CloudWatch、CloudTrail、EC2、RDS、成本、安全发现、Support case,但**不会改任何东西**。唯一会写的是 AWS Support case(建案 / 回复 / 关闭),而且必须你点确认按钮才执行 —— 详见 §8。
2. **每一次提问都针对一个具体的 AWS 账号**。顶栏的账号选择器决定这一句问的是哪个账号;每条回答的页脚都会印出它到底答的是哪个 12 位账号 ID,避免你把旧回答当成当前账号的结论。
3. **会话默认保存 30 天**。服务端到期自动清理(每次使用会刷新这个计时)。要长期留存的结论,用**长报告下载**(§4.8)存到本地。

### 1.6 两步验证(验证器 App)

开着两步验证时,登录除了密码,还要输入验证器 App(Google Authenticator、Microsoft Authenticator、1Password 等)生成的 6 位验证码。部署这套 NotiOps 的人三选一(一键部署是参数 **Two-step verification at web sign-in**,`setup.sh` 是 `MFA_MODE`):

| 档位 | 你会遇到什么 |
|---|---|
| **可选**(默认) | 在左下角菜单 **两步验证** 里自己开:点 **开启** → 扫码 → 输入 6 位验证码。开了之后每次登录都要验证码,也可以自己关。**「管理」页要求先开** —— 没开的管理员点进「管理」只会看到 **先开启两步验证** 和一个 **现在开启** 按钮 |
| **强制** | 下次登录时(新用户是改完初始密码之后)直接要求绑定,之后每次都要验证码;菜单里只能 **换一个验证器**,不能关 |
| **关闭** | 只用密码,菜单里没有这一项 |

- 二维码在你的浏览器里生成,不经过任何第三方;手机扫不了就手动输入二维码下面那串密钥。
- **换手机**:旧手机还在,就在菜单里点 **换一个验证器**,用新手机扫码;验证成功后旧手机上的验证码作废。
- **手机丢了、登录不进去**:请管理员在 **管理 → 用户** 里你那一行点 **重置两步验证**。你所有已登录的会话会被退出,下次登录时重新绑定(「可选」档下,在你重新开启之前登录只要密码)。
- 管理员自己丢了手机、又没有别的管理员能帮忙:有这个 AWS 账号权限的人可以用 AWS CLI 重置,命令见 [DEPLOYMENT_ONECLICK.md §8](DEPLOYMENT_ONECLICK.md#8-安全说明值得知道的几条)(两种部署方式都适用)。
- IM 机器人不受影响:它们不走网页登录。

### 1.7 忘记密码与账户设置

**忘记密码**,看你的账号有没有绑定**已验证**的邮箱:

| 情况 | 怎么办 |
|---|---|
| 绑定了已验证邮箱 | 登录卡片上点 **Forgot password?** → 输入用户名或邮箱 → **Send code** → 到邮箱收 6 位验证码(1 小时内有效)→ 输入验证码和两遍新密码 → **Reset password** → 用新密码登录 |
| 没有邮箱(或邮箱没验证) | 收不到验证码。请管理员在 **管理 → 用户** 里你那一行点 **重置密码**:他会拿到一个临时密码转告你(7 天内有效),你用它登录后马上设自己的新密码 |
| 你就是唯一的管理员 | 有这个 AWS 账号权限的人用 CLI 重置,命令见 [DEPLOYMENT.md](DEPLOYMENT.md) / [DEPLOYMENT_ONECLICK.md §8](DEPLOYMENT_ONECLICK.md#8-安全说明值得知道的几条)(两种部署方式都适用) |

- 账号没有已验证邮箱时,点 **Send code** 会直接提示找管理员重置;其它情况都显示同一句「如果这个账号有已验证邮箱,验证码已经发出」(不显示发到哪个地址)。没收到码先看垃圾邮件,再找管理员。
- 验证码邮件的发件人是 `no-reply@verificationemail.com`,标题是 `Your NotiOps verification code`。不是你自己点的,忽略它并告诉管理员。
- 同一个账号每小时能请求 / 输入验证码的次数有限(Cognito 按风险定,5–20 次),超了会提示过一会儿再试。
- 两步验证不受影响:重置密码之后登录照样要 6 位验证码。手机也丢了,再请管理员 **重置两步验证**(见 [§1.6](#16-两步验证验证器-app))。
- 管理员在 Cognito 控制台点过「重置密码」的账号,登录时会直接进入输验证码这一步,可以点 **Send a new code** 重发。

**账户与密码**(左下角菜单):

- **邮箱**:绑定、更换、验证。验证码发到新邮箱(24 小时内有效),确认之前原来的邮箱照常能登录、能收码。**建议每个人都绑一个** —— 以后忘了密码就能自己找回。没绑邮箱时,头像上有个橙色小点。
- **修改密码**:输入当前密码和两遍新密码(至少 8 位,含大写字母、小写字母和数字)。
- **退出所有设备**:退出你在所有设备上的登录(包括这一台),其它设备最长 1 小时内失效。怀疑密码被别人知道了、或刚在登录页重置过密码时用它。

## 2. 左侧导航:每个入口分别干什么

先看全貌 —— 关键是分清哪些是**对话主题**、哪些是**仪表盘**:

| 入口 | 形态 | 什么时候用它 |
|---|---|---|
| **通知**(Notifications) | 仪表盘(收件箱) | 想看「有没有出事」:AWS Health、告警、成本异常、Trusted Advisor、GuardDuty 都汇在这里 |
| **调查**(Investigation) | 对话主题 **+** 7 个运行仪表盘 **+** 4 个安全仪表盘 | 有一个具体故障要排查;**安全类问题也在这里问**、安全看板也在这里(见 §2.4);或者先扫一眼告警 / 变更 / 备份 / EOL 面板再决定查哪个 |
| **成本**(Cost) | 对话主题 **+** 仪表盘 | 月度成本复盘、找涨价驱动因素、看 SP/RI 覆盖、按标签拆账 |
| **案例**(Cases) | 对话主题 **+** 4 个仪表盘 | AWS Support case 全生命周期:看、分析、建、回、关 |
| **巡检**(Inspection) | **只有仪表盘,不是对话主题** | 看 NotiOps 自动巡检出的高负载 / 闲置资源,并派 AI 判读 |
| **技能**(Skills) | 管理页 | 把你的流程和团队规范写成 Skill,让它按你的方式做事 |
| **定时任务** | 管理页 | 按计划自动用一个 Skill 发起 DevOps Agent 深度调查,结果写成会话并发通知(默认只有管理员看得见,见 §5.8) |
| **管理**(Admin) | 管理页 | 在「更多」里(2026-10-10 起);模型、角色权限、账号接入等控制台设置,**只有管理员看得见** |
| **What's New** 卡片 | 对话主题 | 跟 AWS 新发布,并结合你账号在用的服务 |

> **侧栏里没有「安全」这一项。** 安全的**聊天**能力本来就是「调查」的子集,所以并进了调查;安全的**仪表盘**一个没少,入口是调查输入框上方的「**安全态势**」胶囊(见下)。

点一个**对话主题**,进的不是空白聊天,而是这个主题的**着陆页**:呼吸 logo + 一句主题标题 + 4 张随机起手卡片 + 输入框。

**带仪表盘的主题,入口都在输入框上方那一行胶囊上** —— 与聊天框**左对齐**、单行不换行(窄屏横向滚动)、行首**没有**任何分类标签:

| 主题 | 胶囊 | 点进去是 |
|---|---|---|
| 调查 | ⟨运行概览⟩ ⟨安全态势⟩ | 7 个运行仪表盘 / 4 个安全仪表盘(§2.2、§2.4) |
| 成本 | ⟨支出与优化⟩ | 成本仪表盘(§2.3) |
| 案例 | ⟨案例进展⟩ | 4 个案例仪表盘(§2.5) |

胶囊名字刻意做成**粗粒度**:一颗胶囊 = 一棵看板树,以后往树里加面板不会在这一行多出胶囊。这一行在着陆页和会话里都在;从胶囊进去的看板,页头左上有**返回**按钮,回到你刚才那个会话。



### 2.1 通知(Notifications)

导航第一项,标签旁边有**未读红点数字**(超过 99 显示 `99+`,大约每 60 秒刷新一次)。**打开这个页面,就把全部通知标记为已读**,红点当场归零 —— 没有「全部标记已读」按钮,也没有已读 / 未读筛选器。想留一条稍后处理,得自己记下来。页头有一个 **↻ 刷新**,不必等 60 秒轮询。

页面右上角还有**这一页自己的账号选择器**。它只切换 **AWS Health 与生命周期/EOS** 的账号视角,**不过滤收件箱** —— 收件箱是账号级共享的一份。

左侧分两组、共 **4 + N** 项:

**(A) AWS Health(实时调 AWS Health API,3 个区块 + 1 个需单独授权的子页)**

| 区块 | 里面是什么 |
|---|---|
| **服务运行状况** | AWS 侧的公开事件。右上角一个「**状态历史**」外链 |
| **您的账户运行状况** | **只**列与你账户相关的 issue(scope 非 PUBLIC)。右上角一个「**在控制台查看**」外链 |
| **计划的更改** | **独立的第三个区块**(不是账户运行状况的一部分):有 **日历**(默认) / **列表** / **时间轴** 三种视图,顶部是「未来 7 / 30 / 60 天 · N 项变更」计数卡 |
| **生命周期 / EOS** | 见下面 (B) |

- 每个区块**一次最多列 50 条**(总共最多取 300 个事件,每条描述裁到 800 字),超出时底部写「还有 N 条,去控制台查看」。
- 每张卡片有「**显示完整通知**」,点开才按 ARN 去拉详情;拉不到时写「详情加载失败,请重试或去控制台查看。」
- 没有 Business / Enterprise Support 计划时整块直说「Health Dashboard 需要 Business 或 Enterprise Support 计划。可直接在控制台查看。」
- ⚠️ **组织级(全组织)Health 视角当前跑不起来** —— 部署的 IAM 没有对应权限,所以「全组织」这个范围标签和「影响面最大」那一行**不会出现**。

**(B) 生命周期 / EOS**(AWS Health 分组的第 4 项 —— 通知主题里体量最大的一块)

全区域扫描 **RDS / Aurora、EKS、Lambda、ElastiCache、OpenSearch、EMR**,给你:

- **4 张风险卡**:已过期 / 7 天内 / 30 天内 / 90 天内到期的计数
- **受支持比例**、**按服务的风险分布**
- **即将到期清单**(每行写「剩 N 天」或「已过期 N 天」)
- **AWS Health 结束支持通知**(这一段是**权威来源**,来自 AWS 自己)
- 页脚写明**已扫描 N 个 region**;结果服务端**缓存 60 分钟**
- 切到组织视角时还有「**按账号风险分布**」,点一个账号可以下钻

> ⚠️ 这一项有**独立的能力门禁**(`nav:notifications:eos`)—— **拿到「通知」入口并不等于拿到它**。6 个预置角色里**只有管理员**看得到;别的角色看不到这一项不是 bug,是没授权。

**(C) 事件通知(持久化收件箱,红点的来源)**

每一类事件一个入口,后面带条数角标(角标用的是**整个收件箱的真实条数**,不受显示上限影响)。

卡片上的动作**两种卡片不一样**,这一点最容易踩:

| 卡片 | 有哪些按钮 |
|---|---|
| **Health 事件卡** | 深入调查 / 就此提问 / 显示完整通知 —— **没有控制台按钮**(控制台入口在区块级) |
| **收件箱事件卡** | 深入调查 / 就此提问 / 控制台(仅当该事件带链接时)/ 显示完整通知(仅当有正文时) |

两个同名按钮,**成本模型完全不同**:

| 按钮 | 从哪张卡点 | 会发生什么 |
|---|---|---|
| **深入调查** | **收件箱卡** | 新建一个「调查」会话,**自动打开「深度调查」开关**(0 token,BFF 直连 DevOps Agent),并把准备好的调查描述**立即发送** |
| **深入调查** | **Health 卡** | 同样新建会话并立即发送,但**不开任何深度调查开关** —— 走的是「调查」主题的常规模型 + 只读工具去交叉比对受影响资源,**会消耗模型 token** |
| **就此提问** | 两种卡都有 | 新开一个普通会话,把事件内容带过去,由模型即时回答 |

> ⚠️ 两条注意:
> 1. 这两个按钮都是**点下去就发**,不会先把 prompt 填进输入框等你改。
> 2. **只有「深入调查」会带上你在通知页选中的账号,「就此提问」不带** —— 多账号环境里,「就此提问」可能问到的是聊天侧当前那个账号。
>
> 收件箱**永远不会自己发起调查**,一定是你点了才动。收件箱是**账号级**的(同一个账号的所有人看到同一份),5 分钟内的重复事件会去重(Trusted Advisor 检查项的反复刷新按 24 小时算),条目约 90 天后自动过期,列表**一次只显示最新 200 条**,被截断时分组底部会如实写「显示最新 {n} 条,共 {total} 条」(连总数都查不到时写「显示最新 {n} 条,还有更早的通知未显示」)。

**开箱默认收 5 类事件** —— 但**每一类都还有硬过滤**,这是「开了却收不到」最常见的原因:

| 事件源 | 实际只推什么 |
|---|---|
| **AWS Health** | 只推 `category=issue` 的**实际影响事件**。计划变更 / 账户通知**不进收件箱**,它们只出现在上面的 Health 实时视图里 |
| **CloudWatch 告警** | 只在告警**进入 ALARM 状态**时推 |
| **GuardDuty** | 只推 **severity ≥ 7.0** 的发现 |
| **Trusted Advisor** | 只推 **status=ERROR** 的检查项 |
| **Cost Anomaly** | 成本异常检测发出的异常 |

另外 5 类**默认关闭**:AWS Backup、EC2 Spot 中断、Auto Scaling 启动失败、RDS 实例事件、Config 合规。默认关闭的类型只有在真的来过一条事件之后才会出现在左侧;空的时候会写「暂无此类事件。该事件源默认关闭,需先启用对应的 EventBridge 规则。」要打开:方式 B 在部署时加 `-c webNotifBackupJob=on` 这类参数;方式 A 去 EventBridge 控制台把对应规则 **Enable** 即可(两条路径规则名同源)。

> ⚠️ 三条部署差异:
> 1. **成本异常**和 **Trusted Advisor** 这两个事件源只在 **us-east-1** 发得出事件(AWS 侧就是全局服务)。方式 B 在别的区部署时会给一条 synth 警告,方式 A 只在规则描述里写明。
> 2. **方式 B 会把 NotiOps 自己的 `notiops-inspection-*` 运维告警排除掉;方式 A(一键 CFN)当前没有这道过滤** —— 一键部署的收件箱里可能出现 NotiOps 自己的运维告警。这是已知缺口,按「两条路径功能对等」在补。
> 3. `/health/dashboard/count`、「其他通知」、「事件日志」、「未处理 issue 数」这几样后端返回了、但**界面上没有任何组件渲染**,别照着找。

### 2.2 调查(Investigation)

主题标题「排查一下你的 AWS 环境」,进对话后的空态提示「想排查哪个资源?」。这是 NotiOps 最深的一个主题 —— 输入框下方平铺着**两枚开关**(默认都不开,详见 §4.3):

> 🔴 **安全类问题现在也在这里问**(2026-09-11 起「安全」不再是对话主题,只保留仪表盘)。原因很直接:安全的对话侧只挂 8 个核心工具、system prompt 也没有任何安全专属内容,而调查这边是完整的 21 个 CloudWatch + CloudTrail 只读工具 —— 同一句安全问题在「安全」里问,答得**比在这里问更差**。所以起手问句的池子从 6 句扩到 **12 句** —— 原来安全主题那 6 句整组并了进来:安全风险发现、公开可访问的 S3 桶、对 `0.0.0.0/0` 开放的安全组、IAM 权限风险审查、没启用 MFA 的 IAM 用户、云安全最佳实践。着陆页每次从这 12 句里抽 4 张卡,会话里那排小 chip 抽 3 个(抽样数没变,只是刷出来的组合更多样)。

| 档位 | 谁来答 | 用时 | token |
|---|---|---|---|
| **两枚都不开**(默认) | NotiOps + 本主题的只读工具集 | 秒级 | 计费 |
| **DevOps 对话** | 你自己的 AWS DevOps Agent,流式 | 秒级 | **0**(计入你的 DevOps Agent) |
| **深度调查** | 派给 DevOps Agent 做多信号根因排查,BFF 直连它的 API | 几分钟 | **0** |

> 🔁 2026-09-13 起这里只有**一枚**「深度调查」,而且是 **0 token** 那一条。之前有两枚同名的:一枚先花 token 让 NotiOps 的模型去转交、一枚标着「(直连)」绕过模型直连 API。同一个能力两个入口、区别只在要不要先烧一次 token,没人有依据去选 —— 所以留下直连那条,「(直连)」这个限定词也一起去掉了。

> ⚠️ 一个已知的显示不一致:在**调查主题**里,直连路径的回复落库时不带来源标记,**刷新之后页脚会显示成「AWS Bedrock (<模型名>)」而不是 AWS DevOps Agent**。当轮显示是对的,刷新后会变。计费口径不受影响 —— 那一轮确实是 0 token。

**默认档(两枚都不开)就能干很多事**:这个主题会挂上**完整的 CloudWatch + CloudTrail 只读工具集**(21 个工具;其他主题只挂 8 个核心的),所以你可以直接问当前告警、告警历史、指标、日志组、Logs Insights 查询,以及 CloudTrail 的 `lookup_events` / `lake_query`。另外每个主题都有原生只读 boto3 工具:RDS 实例列表 / 详情 / 近期事件 / 指标,EC2 实例列表 / 详情(含 `stateReason`、`stateTransitionReason`,所以「它昨晚为什么重启」问得出来)、安全组。

**仪表盘有 7 个**(点输入框上方的「**运行概览**」胶囊进;另一颗「安全态势」进的是 §2.4 那 4 个):

1. **告警总览** —— ALARM / OK / 数据不足 的计数 + 活跃告警列表
2. **当前告警** —— 每一行都有 **调查** 和 **通知** 两个按钮
3. **最近变更**
4. **Backup 健康** —— 7 天作业总数 / 失败数,每个失败作业一个「调查」按钮;没用 AWS Backup 或没权限时写「Backup 数据不可用(未用 AWS Backup 或无权限)。」
5. **AWS Health** —— 需 Business / Enterprise Support,否则写「AWS Health 不可用(需 Business/Enterprise Support)。」并给一个「打开控制台」链接
6. **EOL 风险** —— 多区域扫描(界面会提示最长约 45 秒),给出「有风险 / 总数 / 支持率」,超时可重试
7. **事件收件箱**

> 仪表盘上的「**调查**」按钮**故意不打开深度调查** —— 它只是替你写好一句给模型的提问,秒级出结果。只有**事件收件箱**卡片上的按钮会带上「深度调查」。
>
> ⚠️ **2026-09-11 一起下线的东西**:「调查」和「安全」原来各有一个**缩略卡落地页**(几张小卡片带个数字,点开才进详情),落地页顶上还有一张组织级的「**按账号分布**」概览卡(调查看告警、安全看 GuardDuty 高危 + TA 问题,点一行下钻到该账号)。改成「胶囊 + 两栏浏览器」之后这两个落地页整体删了,那两张概览卡也**跟着没了**。后端接口(`/investigate/alarms/org-summary`、`/security/org-summary`)**还在**,以后要重做「按账号态势」直接取,不用重写后端。

### 2.3 成本(Cost)

主题标题「一起优化你的云成本」。导航标签是「**成本**」(不是 FinOps)。

**对话侧**:在这个主题里,NotiOps 会额外挂上两个 AWS 官方 MCP server(`aws-pricing-mcp-server` 和 `billing-cost-management-mcp-server`)作为进程内子进程,收敛到一份 **18 个只读工具的允许清单**。所以「本月成本为什么涨了」「哪些实例最贵」「SP 覆盖率多少」这类问题能拿到真实数据。

> ⚠️ 两点边界:(1) 这两个 MCP **只在成本主题挂**,别的主题只有 7 个核心工具;(2) **切到成员账号提问时不挂**(它们的凭证钉在部署账号上),这时改用原生 boto3 只读兜底,能力略窄。
>
> **Amazon Nova Pro** 自 2026-10-10 起在模型目录里默认停用,模型菜单里一般看不到它;管理员若在「更多 → 管理 → 模型」里把它重新勾上,它在这个主题会被标上「不推荐」,注明「成本分析不推荐(建议用 Claude / DeepSeek)」。

**仪表盘**(点输入框上方的「**支出与优化**」胶囊进)默认能看到 **7 个**:支出概览、优化与风险、关键进度、环比变化、成本深挖、按标签查成本、成本异常。另外 4 个 **CUR 报表**(费用趋势 / Credit / 扩展支持 / Savings Plans)只有接上了**成本 MCP server** 才出现 —— 没接就整块不显示,接了则左侧栏最多列到 **11 项**。两条部署路径**默认都不接**,要在部署时打开,两种接法二选一:

- **让 NotiOps 替你部一个**(推荐):方式 B 用 `COST_MCP_SELF_HOST=true ./setup.sh`;方式 A 在参数页填 `CurTable=<库>.<表>`(已有 CUR)或选 `ProvisionCur=yes`(让它连 CUR 一起建)。它只查**部署账号、部署 Region 里**的 CUR —— CUR 在另一个账号的情况这一版暂不支持,那种情况用下一种接法。
- **指向你自己已经在跑的那个**:方式 B 给 `COST_AGENT_MCP_URL` + `COST_AGENT_FN_ARN`;方式 A 填 `CostAgentMcpUrl` + `CostAgentFunctionArn`。

新建的 CUR 要等 AWS 首次交付(最长 24 小时),在那之前这 4 张显示「客户 CUR 数据源暂时不可用」,就绪后自己接上,不用再部署一次。详见 [DEPLOYMENT.md §14.2](DEPLOYMENT.md) 与 [DEPLOYMENT_ONECLICK.md §2.12](DEPLOYMENT_ONECLICK.md)。

**成本深挖**是 4 个场景(CloudWatch / 数据传输 / EC2 计算 / S3 存储),走 Athena 上预置的具名查询,输出「AI 洞察(请核对)」和「下载原始数据 CSV ↓」。这些具名查询由 NotiOps 在 CUR 第一次就绪的那一刻自动建出来:方式 B 的「CUR + Athena」那一步(新建或复用都算)默认就会走到;方式 A 只有选了 `ProvisionCur=yes` 才有,只填 `CurTable` 不算(见 §8.6)。没建这些具名查询时,它会明确报 `no_named_queries` / `named_query_not_found`,而不是给你一张空表。

所有成本页脚都有一句:**不含 support、折扣、税;成本数据约 1–2 天延迟**。

### 2.4 安全态势(Security posture)—— 调查主题下的一组仪表盘

> 🔴 **2026-09-11 起「安全」不再是对话主题,侧栏里也不再有这一项**,只保留这 4 个仪表盘。安全类**提问**请去「调查」(§2.2) —— 那边工具更全,答得更好;原来安全主题的 6 句起手问句也整组并到了调查的池子里。
>
> **入口只有一个**:进「调查」,点输入框上方那颗「**安全态势**」胶囊。页头左上有**返回**按钮,回到你刚才那个会话。
>
> 老会话怎么办:库里那些标着「安全」的历史会话会**自动显示成「调查」**(读的时候归一,不需要你做什么),继续在里面提问走的就是调查的完整工具集。

**仪表盘有 4 项**,都按卡片单独鉴权:

| 卡片 | 里面是什么 | 需要注意 |
|---|---|---|
| **TA 安全建议** | 三色汇总(正常 / 需关注 / 有风险)+ 检查项清单 + 点开某项下钻到**被标记的资源明细**,每一行还有自己的「调查」按钮 | 需 Business / Enterprise Support(否则写「需 Business / Enterprise Support 计划。」);⚠️ Trusted Advisor **固定读 us-east-1**,和你部署在哪个区无关;**检查项名称与下钻表头恒为英文** |
| **Security Hub** | **四档严重度计数**(Critical / High / Medium / Low)+ **高危发现 Top 8** | ⚠️ 只查**部署 region** 的活跃发现;计数按一次 `GetFindings`(ACTIVE + NEW/NOTIFIED,**最多 100 条**)算,所以是**抽样**、发现多时会偏低;没开时写「Security Hub 未开通。」 |
| **GuardDuty** | **四档严重度计数**(Critical / High / Medium / Low)+ **Top 8 高危发现**(标题、分值、发现类型 · 区域,每行一个「调查」按钮) | ⚠️ 只查**部署 region** 的活跃发现,而且只用**第一个** detector;没开时写「GuardDuty 未开通。」 |
| **安全公告** | AWS 官方公开安全公告,**最近 30 天** | 公开源,所以即使跨账号凭证有问题它也照样能显示 |

每张卡片(以及 TA 下钻表格的每一行)上的「**调查**」按钮会交棒到一个新的「调查」会话,并且**不打开深度调查** —— 它只是替你写好一句提问。服务端对每个账号**缓存 5 分钟**,所以刚在 AWS 侧处理完的发现不会立刻消失。

> **想看全组织、全区域的 Security Hub**,需要另做 Security Hub 委派管理员 + `ALL_REGIONS` Finding Aggregator。方式 B(`setup.sh`)在多账号部署时会问一句(**默认不开**);方式 A(一键 CFN)没有这一步,要自己去控制台做。
>
> **谁能看见这颗胶囊**:管理员一直能看见;非管理员要有 `nav:security`。6 个预置角色里**支持/运维**和**只读查看**带这条权限(2026-09-11 补的 —— 在此之前一个都没有,结果是"安全模块只有管理员进得去",这不是设计意图);其余角色仍需管理员显式授予。这颗胶囊是 **fail-closed** 的 —— 能力接口异常时非管理员会暂时看不到它(同一行的「运行概览」相反,是 fail-open)。⚠️ 因为它挂在「调查」主题里,**没有 `nav:investigate` 的人根本走不到这一行** —— 只读查看角色目前正是这种情况(见 §2.10)。
>
> ⚠️ 权限是**按卡片**生效的:关掉某张卡的权限,BFF 会连数据一起剔掉,左侧那棵树里也不再列它 —— 不会给你一个点进去空白的面板。
>
> ⚠️ 方式 A 有一个部署参数 `AgentReadOnlyAccess`(默认 Yes),它决定的是 agent **能读多宽**,不是能不能写:Yes 给 agent 的角色挂上 AWS 托管的 `ReadOnlyAccess`;改成 No 就只剩精选的几组只读授权(成本、日志、指标、RDS / EC2 describe 等),范围更窄 —— 比如 Security Hub / GuardDuty 的发现它就读不到了,在对话里问这类安全问题会因缺权限答不上来。两种取值下,agent 的角色对你的基础设施都没有写权限。

### 2.5 案例(Cases)

主题标题「处理你的 AWS Support 案例」。**Support case 相关的 9 个工具挂在每一个非 IM 主题上**,所以你在任何会话里都能问 case,不必先切到这个主题。

**能做的事**:

- **看**:「列出我所有未结的 cases」—— 支持 `open` / `resolved` / `all`,默认 20 条,最多翻 3 页 / 扫 300 个 case,按创建时间倒序。
- **读**:打开某个 case 看它的往来记录(最多 10 条最近通信,每条正文裁到 2000 字;还能继续翻页)。
- **建 / 回 / 关**:三个动作都是**建议 → 你确认 → 执行**,详见 §8。

**怎么建案:说意图就行,不用等模版**

只要说出意图(比如「帮我创建一个新的 support case」),助手会**直接弹出一张可编辑的「创建支持案例」卡片**。⚠️ 它**不会**再给你一份文字模版让你填了发回来 —— 别等,那份模版不会来。

卡片上的字段:

| 字段 | 说明 |
|---|---|
| **服务** | ⚠️ 不是下拉箭头,是一个「**输入以搜索服务**」的搜索框 + 联想列表(加载时显示「加载中…」)。候选来自实时的 `DescribeServices` 目录,按界面语言缓存 6 小时,**条数随 AWS 上新变化**,界面上不显示总数 |
| **类别** | 跟着服务联动;没选服务时提示「请先选服务」 |
| **案例类型 / 严重等级 / 语言** | 都有默认值 |
| **问题描述** | **必填**,上限 **2000 字符** |
| **开到哪个账号 \*** | 只在「部署账号 + ≥1 个已启用成员账号」时出现,单账号部署整块不显示 |

- 「**预览**」按钮要等**主题、服务(必须选中目录里的真实服务)、类别、问题描述**都齐了才可点,并且这张卡尚未执行过。
- 目录拉不到时卡片会出警告,此时服务 / 类别校验会**放宽**。
- 点「**取消**」不会向后端发任何请求。
- 确认创建后,卡片直接给案例号和「— 在 AWS 控制台打开」,并标「**已验证**」(系统回查到了该案例)或「**状态待确认**」—— **后者不代表建案失败**。

**如果你自己贴一段结构化字段过来**(比如从别处复制的一段「标题 / 服务 / 严重等级 / 问题描述」),助手会把它解析成一张**只读预览卡**让你确认后直接建案。解析不出服务时卡上写「(未能匹配到服务,请返回补充服务名)」且「确认创建」不可点。

**建案之前它会先探权**(`case_capability`,15 分钟缓存)。探失败就直接告诉你原因(`support_plan_required` / `access_denied` / `cross_account_unavailable`)和**缺哪几条 IAM action**(`support:DescribeServices`、`support:DescribeSeverityLevels`、`support:CreateCase`),而不是让你填完一张注定失败的表单。

> AWS Support API 需要 **Business / Enterprise On-Ramp / Enterprise** 支持计划。Basic / Developer 计划下,建案卡片会被替换成一段中英双语说明 + 一个「打开 Support Center」控制台链接。

**案例仪表盘**(点输入框上方的「**案例进展**」胶囊进,左上「← 返回」回你刚才那个会话)—— 左栏 **4 项**:

| 页面 | 里面是什么 |
|---|---|
| **未结案例概览** | 按严重级别的环图 + 按服务 Top 5。多账号时顶部还有一张「**组织概览 · N 个账号 · M 个进行中案例**」卡(**15 分钟缓存**;⚠️ **只覆盖成员账号,不含部署账号**;取不到数的账号会单独提示) |
| **等你回复** | 球在你这边的案例,每条带「已等待 N 天」 |
| **高危 / Incident** | 高严重度与 Incident 类案例 |
| **响应健康** | 达标 / 临界 / 超目标 三列 |

> ⚠️ 两条口径:
> 1. 「响应健康」是 NotiOps 自己的**估算,不是官方 SLA**(`DescribeCases` 不返回 SLA 字段)。算法是「距最后一次往来的小时数」对比按严重度设的目标:critical 0.25h / urgent 1h / high 4h / normal 12h / low 24h。
> 2. 仪表盘统计**只取最近 100 条案例**。
>
> 侧栏里**没有「趋势分析」这一页** —— 别按「6 个月趋势 / AI 建议」去找,现网没有入口。同理,案例主题**不挂 DevOps Agent**,§4.3 那两枚开关在这个主题一枚都不显示;案例列表里也没有「一键升级为 Support case」按钮。
>
> 案例主题的推荐问题芯片是**用你真实的案例数据**拼出来的(比如「看看我的 3 个未结案例」「分析最近案例 #<案例号>」),所以每个人看到的不一样。

### 2.6 巡检(Inspection)

**巡检刻意不是对话主题** —— 点它直接进仪表盘,没有着陆页。它看的是 NotiOps 自己定时跑出来的巡检结论。

两组、**4 个页面**:

- **巡检发现**:**高负载**、**闲置与成本**
- **配置**:**巡检范围**、**阈值与定时**

点开一条发现是一个**只读抽屉**(三种方式都能关)。抽屉里有一个「**深入分析**」按钮:填一段可选的「补充背景(可选)」→ 点「派发判读」,它会真的派一次 DevOps Agent 判读,然后提示「判读已派发,1~3 分钟后回来。点右上角「刷新」查看。」并打上 ⏳ **判读中** 角标。**同一条发现不能派第二次判读**(按钮不再出现)。

**手动触发一次巡检**时,确认框会把代价写清楚:「会真调 GetMetricData 并派 AI 判读(都计费)、占掉今天的巡检槽位、撤不回来;今天已成功跑过的账号会跳过。」

> **两件必须知道的事**:
> 1. **一键部署(方式 A)完全没有巡检** —— 侧栏「更多」里根本没有「巡检」这一项(整个页签不下发,见 §2.10)。只有浏览器里还缓存着旧版前端、或直接调 `/inspection/*` 接口时,才会碰到「这套部署暂不支持资源巡检」和「一键部署(方式A)的最小底座只装 Web Chat…需要巡检请用完整部署(方式B,setup.sh)」这条提示(接口回的是 `inspection_not_deployed`)。
> 2. 全量部署(方式 B)装完巡检就在跑,**不用先去启用什么**:部署账号每次部署都会被自动接入,两类巡检(高负载 / 闲置)默认每天 **02:00 UTC** 各跑一轮,默认扫部署账号的全部 region;调度器每 15 分钟醒一次,只是看到没到点。和手动触发一样,每一轮都会真调 GetMetricData,有发现时还会派 DevOps Agent 判读(都计费)。执行时刻在「阈值与定时」里改;要把别的账号也纳入巡检,去「更多 → 管理 → 账户」接入(见 §6.4);不想扫的资源在「巡检范围」里加排除。巡检结论写进独立的表。
>
> 「巡检范围 / 阈值与定时 / 手动触发」这几个动作,**6 个预置角色里没有一个**带对应权限,只有管理员(权限 `*`)能操作。

### 2.7 Skills

Skills 是侧栏「**更多**」里的一项(不在「定制」里面),中文界面下这一项显示为「**技能**」。它让你把团队流程、规范和专业知识写成一个个 Skill,让 NotiOps 按你的方式做事。详见 §5。

### 2.8 What's New 卡片

它**不在主题列表里**,而是钉在侧边栏最下面的一张卡片:标题 **What's New**,副标题「AWS 最新发布 · 与你的业务结合」。

这是**整个导航里唯一不受权限门控**的入口 —— 谁都看得见。点它新开一个 what's-new 会话,并**预先打开联网搜索**,但**故意先不抓任何东西**:你从 6 张预置卡片里挑一句,或者自己问。

时间窗既可以是回看天数(默认 7 天),也可以是明确的起止日期,所以「上个月」「本月至今」「过去 30 天」都说得通。数据走 AWS 官方 What's New API(分页,最多 60 页 / 2000 条,全历史);API 挂了就退到 RSS,但 RSS 只回溯约 14 天,这时报告里会明确写「时间窗不完整」的警告;两条都挂了就让你改用联网搜索。

问「**跟我账号相关的有哪些**」是真的做了个性化:它会取这个账号最近 30 天 Cost Explorer 花费 Top 12 的服务作为过滤依据(查成员账号时用该账号自己的会话,不会用部署账号的凭证)。

### 2.9 管理(Admin)与定制(Customize)

- **定时任务** —— 在侧栏「**更多**」里、排在「技能」后面。按计划用一个已发布到 DevOps Agent 的 Skill 自动发起深度调查,详见 §5.8。默认只有管理员看得见。
- **管理** —— 8 个页面的管理控制台,详见 §6。它在侧栏「**更多**」里,排在「巡检」「技能」「定时任务」后面(2026-09-11 曾提到一级,2026-10-10 按用户要求收回「更多」),只有管理员看得见。
- **定制** —— ⚠️ 目前**整项不显示**。「更多」折叠组现在收着巡检 / 技能 / 管理,但「定制」仍不放进去(`Sidebar.tsx` 里 `SHOW_CUSTOMIZE_ITEM = false`)。里面的「连接器」和「插件」都还只是「即将上线」的占位,等有内容了再放出来。

### 2.10 看不到某个入口? 那是权限或部署方式决定的

> 先看一眼「更多」展开了没有。**巡检 / 技能 / 管理都收在侧栏「更多」里,而它默认是收起的** —— 只有当前页正好是其中一项时才会自动展开,其余时候要你自己点开(展开 / 收起会被记住)。点开了还是没有,再往下看;三项都不给你显示时(角色没权限、这套部署没装、或被「模块」开关关掉 —— 见下面三类原因),连「更多」这一项本身都不出现。比如在一键部署(方式 A)上,Cognito `member` 组的用户(默认映射到**只读查看**)就整个看不到「更多」:这个角色其实带巡检权限,只是方式 A 没装巡检;技能和管理则不在这个角色里。

导航项显不显示,由**服务端算出来的能力清单**说了算(登录后拉一次 `GET /me/capabilities`)。三类原因:

1. **你的角色没这条权限**。6 个预置角色是:**管理员**、**只读查看**、**FinOps**、**支持/运维**、**开发者**、**服务经理**。要点:
   - **没有任何预置角色**带 `nav:customize`;
   - `nav:security`(安全态势看板)只有**支持/运维**和**只读查看**带 —— 2026-09-11 补的,在此之前一个都没有,等于"安全看板只有管理员进得去";
   - **只有开发者**带 `nav:skills`;
   - ⇒ 所以一个默认的非管理员用户,连「定制」都进不去(何况「定制」眼下对谁都不显示、管理员也一样 —— 它没放进「更多」,`SHOW_CUSTOMIZE_ITEM = false`,见 §2.9)。
2. **这套部署没装那个功能**。有些节点依赖部署时的环境变量:巡检整块依赖巡检表、成本的「每日异常」卡片依赖成本分析函数、4 张 CUR 报表依赖成本 MCP server 的地址。**一键部署(方式 A)把巡检表和成本分析函数硬编码为空**,所以这两样在方式 A 下永远不出现;成本 MCP server 两条路径都默认不接,部署时打开就有(两种接法见 §2.3)。
3. **管理员在「模块」页把整个页签关掉了**。模块开关**优先于**个人权限 —— 关了就是所有人都看不到(对话页签除外,它是常开的)。

> 加载能力清单期间的策略是刻意分开的:**通知 / 调查 / 成本 / 案例 / 技能**在加载中先显示(fail-open),**管理 / 巡检**加载中先不显示(fail-closed)。所以刚打开页面的一瞬间,导航可能会少一两项,别慌。同一套规则也管输入框上方那行胶囊:「运行概览 / 支出与优化 / 案例进展」跟着各自的主题 fail-open,而「**安全态势**」是 **fail-closed** 的 —— 能力清单还没回来时,非管理员会先看不到它。
>
> 权限也管到**卡片粒度**:即使你能进成本或安全页,BFF 也会把你没权限的卡片从返回结果里剔掉,而不是让前端藏一下。

## 3. 端到端走三遍

三条最常走的路,每条都从「你手上有什么」开始。

### 3.1 走查一:凌晨收到 CloudWatch 告警,先定位根因

**你手上有的**:Web 里「通知」的一个红点(本版本 IM 群里收不到实时告警卡片,见 §14)。

1. 打开 **通知**,在「事件通知」里找到那条 CloudWatch 告警。
2. 决定深度:
   - 想**先看一眼**:点「**就此提问**」,新开普通会话,秒级回答。
   - 想**一次问到根因**:点「**深入调查**」—— 它新开一个「调查」会话,并自动打开「深度调查」开关(0 token)。
3. 如果你走的是**默认档**(两枚开关都不开),直接在「调查」主题里追问就行,它有完整的 CloudWatch + CloudTrail 只读工具:
   - 「这条告警最近 24 小时触发了几次?」
   - 「把这个时间段 `/aws/lambda/xxx` 的 ERROR 日志捞出来」
   - 「这段时间有人改过这个资源吗?」(CloudTrail 会按事件名 + 资源 ID + 窄时间窗查,不会漫扫)
4. 如果你开了**深度调查**:
   - 聊天里会出现「🚀 **深度调查已发起**」+ 标题 + 描述 + 调查编号 + 一个 DevOps Agent 控制台深链;直连路径的横幅额外标注「(直连,0 token)」并给一个可复制的**调查编号**。
   - 分析步骤实时流进右侧**思考过程**面板;长时间没有新步骤时会出现一条约 40 秒一次的心跳行。
   - 最长**同步等 14 分钟**(每 8 秒轮询)。超时它会告诉你 AWS 侧还在跑,之后回来说一句「查一下刚才的调查结果」就能续上(直连路径还会给一个「🔄 查看调查结果(0 token)」按钮)。
   - 完成后显示「✅ **调查完成**」,底下是 DevOps Agent 自己的文字,分成 **Summary / Root cause / Mitigation plan** 三段(分别裁到 4000 / 6000 / 4000 字)。**NotiOps 不会再拿模型去二次总结它** —— 你看到的就是原文。
5. **要缓解方案**:结论下面会有一个 DevOps Agent 控制台按钮,它的文案是**条件的** —— 报告里已经有方案时是「🛠️ 在 DevOps Agent 后台查看本次调查(含缓解方案)」,没有时是「🛠️ 去 DevOps Agent 后台生成缓解方案(打开后切到 Root cause 页)」。你也可以直接在对话里说「给我缓解方案」。
6. **留档**:完整调查会写成一份自包含 HTML 报告放到 S3,聊天里以「🌐 在线查看报告」给出链接;紧跟着是「🔍 调查过程 Trace」—— 调查时间线:Agent 每一步查了什么、看到什么(与 IM 报告卡上那颗按钮是同一个页面)。两条都进 Sources,对象约 7 天后被生命周期规则清掉,要长留就下载。调查过程页偶尔没生成出来时,聊天里会明说,并给 DevOps Agent 后台的入口。

> ⚠️ 开着**深度调查**的那一轮,NotiOps 会把所有直接查环境的工具**全部摘掉**,只留派单工具 —— 这一轮它**物理上无法**自己去看 CloudWatch。所以「先秒级看一眼,再决定要不要深挖」是更省时间的顺序。

### 3.2 走查二:月账单涨了,做一次成本复盘

1. 进 **成本** 主题,点输入框上方的「**支出与优化**」胶囊,先看**支出概览**和**环比变化** —— 用眼睛找到涨在哪个服务、哪个账号。
2. 回到对话追问。时间范围**用自然语言说**(没有日期选择器):
   - 「过去 30 天成本 Top 10 的服务,和上一个 30 天比」
   - 「EC2 这块涨的钱主要来自哪些实例类型?」
   - 「我们的 Savings Plans 覆盖率和利用率现在多少?还有多少可省?」
3. 要**拆到具体维度**:用**成本深挖**(CloudWatch / 数据传输 / EC2 计算 / S3 存储 四个场景),它给 AI 洞察 + 原始 CSV 下载;或者用**按标签查成本**页。
4. 要**盯异常**:看**成本异常**页,或者让「通知」里的成本异常事件直接推给你。
5. 要**给老板一份东西**:直接说「把这次复盘写成一份完整报告」。超长内容不会糊在聊天里,而是落到 S3,回复末尾附上**在线看**(约 7 天)和 **Markdown 下载**(约 12 小时)两个链接。
6. **跨账号**:顶栏切到某个成员账号再问。注意成本仪表盘的口径角标会跟着变 —— 部署账号(付款方)显示「组织聚合 (payer)」,成员账号显示「<名称> · <账号 ID>(成本已过滤)」。

> 成本数据约 **1–2 天延迟**,且**不含 support、折扣、税**。做环比时把这两条记在心里。

### 3.3 走查三:自己搞不定,开一个 Support case 并跟到关闭

1. 任何会话里说:「帮我开一个 case」/「帮我创建一个新的 support case」。
2. 它先**探权**。缺支持计划或缺 IAM 权限时,它会直说原因和**缺哪条 action**,而不是让你白填。
3. 通过后给你一张**可编辑的表单卡片**:服务(可搜索)、类别(联动)、案例类型、严重等级、语言、问题描述(≤2000 字)。多账号部署时,卡片上还有一个**账号下拉框**(≥2 个选项时才出现,默认就是当前会话的账号)。
4. 点**预览**核对,再点**创建案例**。这一步走的是 BFF 的 `POST /actions/execute`:**真正的写操作由服务端用你确认过的参数执行,大模型不在写路径上**。
5. 写完之后 BFF 会**回读一次**并返回 `verified` 标记 —— 建案:能查到;回复:能查到**且**最新一条通信与你发的内容一致;关闭:能查到**且**状态是 resolved/closed。卡片上会显示「已核实」还是「状态待确认」,旁边给一个控制台链接。
6. **跟进**:同样的 建议→确认→执行 流程做**回复**和**关闭**,卡片标题是「回复 Support Case」/「关闭 Support Case」,按钮是「取消 / 确认执行」,成功文案是「已成功回复该案例」/「已成功关闭该案例」。
7. **回顾**:去案例仪表盘看「等你回复」和「响应健康」,或者问「最近 30 天我提过哪些 cases?」。

> 从一次调查转 Support:「转人工支持」**按钮已经被下掉了**(§8),但能力还在 —— 直接说「把这个转人工」/「帮我开个 case」,它会走到建案卡片。

## 4. 跨主题的通用机制

这一节里的东西在**每个主题**都一样,学一次就够。

### 4.1 账号切换器(顶栏)

- 位置在**对话顶栏**(不是输入框工具栏),提示语「切换本视图的账号视角」。第一项是**部署账号**,后面是每个已接入的成员账号,显示成「名称 · 123456789012」。
- **单账号部署时整个下拉框不显示** —— 没得切就不占地方。
- 选择是**按会话记的**;**仪表盘另有一份独立的选择**,两边互不干扰。
- 选中的账号随每条消息以 `account_id` 发出,并且每一轮都重新告诉模型「当前账号 = …」,后面跟一条硬性指令:**不许混账号**。
- 每条回答的**页脚印出它答的是哪个 12 位账号**:成员账号是橙点,部署账号是蓝点。
- 建案卡片自己还有一个账号下拉框(§2.5)。

### 4.2 模型选择

- 位置在**输入框工具栏最右**,显示当前模型名 + 一个小三角。选择**只对这个会话生效**,并且记住。
- **你看到的列表 = 管理员在「更多 → 管理 → 模型」里启用的那一份**(登录后从服务端 `/models` 拉)。内置兜底目录是:**Kimi K3**(内置默认)、Grok 4.7、GLM 5.3、Claude Sonnet 5.5、Claude Opus 5.5、DeepSeek V3.2、GPT-5.6 Terra、GPT-6 Sol。新会话默认用管理员设的默认模型(没改过时同样是 Kimi K3)。
- 目录还在读的时候菜单写「正在读取可用模型…」;管理员一个都没启用时会明说,并且**发送按钮禁用**。读不到服务端目录时会出现一条琥珀色降级横幅 —— 它不会假装内置列表就是管理员的列表。
- **Claude Haiku 4.5** 和 **GPT-5.6 Luna** 已退役、选不到;2026-10-10 起 **Grok 4.6、GLM 5、Claude Sonnet 5、Claude Opus 5、GPT-5.6 Sol** 也换成了上面的同族新版本,**Amazon Nova Pro** 则整个停用。老会话若还钉在这些模型上,会静默回落到目录默认值。
- 管理员若把 Amazon Nova Pro 重新启用,它在**成本主题**里会被标「不推荐」。
- 当这一轮由**你自己的 DevOps Agent** 回答时,模型选择器**整个消失**(那条路径不经过我们的 Bedrock 模型),但发送照样可用。

### 4.3 谁来答、答到多深

输入框下方是一小排**平铺开关**,决定这段对话由谁来答、答到多深。**默认一枚都不开,由 NotiOps 直接回答。**

> 🔁 2026-09-13 改过一次:原来是一个叫「回答模式」的下拉框、里面四项。撤掉重复的那一项之后每个主题最多只剩两枚,藏进一个还要先点开的下拉纯属多一层点击,所以拆回平铺。同一次改动里去掉了成本主题那个永久置灰的「FinOps」占位项。

- 这些开关**互斥**:打开一个会自动关掉另一个,所以一轮不可能被派去两条路。选择**按会话记住**。
- 各主题给的开关不一样:

| 主题 | 工具条上有哪几枚 |
|---|---|
| **调查** | **DevOps 对话**、**深度调查**(两枚) |
| **成本** | **深度调查**(一枚) |
| **通用 / 案例 / What's New** | **一枚都没有**(这排整个不渲染) |

鼠标停上去,tooltip 一句话讲清「谁来答 + 多久 + 代价」:

| 开关 | tooltip 写的是 |
|---|---|
| **DevOps 对话** | 直接和你自己的 AWS DevOps Agent 对话 —— 0 token、免模型配置,用量计它那边;代价:本轮不挂 NotiOps 的工具与 Skills |
| **深度调查** | 交给 AWS DevOps Agent 做多信号根因排查并出报告,通常几分钟、**0 token**;代价:按你的原话透传,不做智能改写。关着就是 NotiOps 用只读工具即时排查 |

> 这几句 2026-09-11 统一收短过 —— 一行只讲「谁来答 + 多久 + 代价」。**「0 token」「不挂工具与 Skills」这类会影响你判断的事实一个都没删**,删掉的是 Bedrock 怎么开通、需审批的动作去哪确认这类细节(那些在本文档里)。

> ⚠️ **「深度调查」现在只有一枚,而且是 0 token 那一条。** 2026-09-13 之前这里有两枚同名的:一枚先花 token 让 NotiOps 的模型去转交、一枚标着「(直连)」由 BFF 直连 API。同一个能力两个入口、区别只在要不要先烧一次 token,没人有依据去选,所以只留直连那条,「(直连)」这个限定词也一起去掉。**老会话里如果记着"转交"那一条,打开时会自动回落到"关"** —— 界面上已经没有它的开关,留着等于开着一个你既看不见也关不掉的东西。

- **「深度调查」只管这一轮**:这一轮结束(答完、你点了停止或出错都算)开关会自动关掉,刷新页面也不会再开着;下一轮还要深度调查就再点一次。从通知或仪表盘点「深入调查」也一样:只有自动发出的第一句是深度调查,后面的追问回到普通问答。对话对象(比如通用会话里选的 DevOps Agent)不受影响,照常留在会话上。
- **调查完可以直接接着说**:深度调查答完、开关熄灭后,接着说「针对上面的问题开一个案例」这类话就行,不用把报告再贴一遍 —— NotiOps 会带上刚才那几轮的结论摘录来接,建案卡的问题和背景按这次调查的结论起草。只带最近一次 NotiOps 回答之后的几轮(最多 3 轮、有长度上限),也不会为了回答追问再发起一次新的调查。
- 点之前,输入框会先探一次这个账号的深度调查可用性。不可用时,依赖 DevOps Agent 的开关会被**置灰并打上「未接入」角标**,tooltip 里写清楚到底是哪种原因(部署账号里没有 Agent Space / 所选账号没接入),已经打开的开关会被自动关掉。探测本身**失败时是 fail-open**(保留可点),而不是把功能藏起来。
- **深度调查没开、但模型硬要用深挖工具**时,它会回一句:「DevOps Agent 深度调查未开启。请在输入框下方打开「深度调查」开关后重试;当前可用本主题的只读工具(告警/指标/日志/事件/资源状态)做即时排查。」
- **0 token 的代价**要知道:你的原话**原样透传**给 DevOps Agent(标题由一个固定函数从你的第一句话里取,描述就是你的原文),它也不会先替你回答概念问题。

### 4.4 「/」命令菜单

在输入框打 `/`(或点工具栏的 `/` 按钮)弹出菜单。

> **这个菜单里只有你的 Skills** —— Web Chat **没有任何内置斜杠命令**。`/case` 那一套是 IM 端才有的。

- 表头是「技能」+ 总条数;每行是 `/<skill_id>` + **预置 / 自建** 标签 + 名称 + 说明。列表**不抽样、不截断**。
- 继续打字筛选(「输入以筛选…」);`↑ / ↓` 移动,`Enter` 选中,`Esc` 关闭。
- ⚠️ **「/」菜单筛的是 `skill_id` 和 Skill 的原始名称,不是界面上显示的本地化名字。** 预置 Skill 的原始名称是英文,所以在中文界面下用「成本」这类中文词在「/」菜单里是**一条都匹配不到**的 —— 请改用 ID(如 `/cost-spike-triage`)或英文词。Skills 页那个搜索框才是按当前语言的显示名匹配。
- 底部固定两个出口:「**管理 Skills**」和「**新建 Skill**」。
- 空态是「还没有 Skill」/「没有匹配的 Skill」。
- 选中后会把「使用 Skill「<名称>」」填进输入框,你可以直接发或者改。
- ⚠️ 输入框的占位符写着「给 NotiOps 发消息…(/命令 · $skill)」,但 **`$` 触发并没有实现** —— 只有 `/` 会弹菜单。

### 4.5 联网搜索

工具栏上的一个开关,**只有一个地球图标、没有文字**(2026-09-13 起把「联网」两个字去掉了 —— 图标本身已经足够,省下的横向空间留给那排平铺开关)。打开后这一轮允许它去公网查(比如 AWS 官方文档、新发布)。鼠标停上去或用读屏软件,都会读到「联网搜索」。**What's New 入口会预先替你打开它。**

> ⚠️ 这个开关**在所有区域都显示**,但底层的搜索能力**只在 us-east-1 接好**。部署在其他区域时,点它不会报错,只是什么也搜不到。

### 4.6 时间范围:没有日期选择器

**Web 里没有任何日期 / 时间范围选择器。** 机制是:每一轮都把**今天的日期**连同模型、联网搜索状态和当前账号一起注入给它,你用**自然语言**说范围就行:

- 「过去 7 天」「本月」「本月至今」「过去 30 天」
- 「上个月」
- 明确日期:「2026-08-01 到 2026-08-31」

它会把这句话翻成工具的起止参数。

### 4.7 两个右侧面板:Sources 与思考过程

两个面板共用同一条右侧轨道,一次只显示一个。

**Sources(来源)**:每条回答的页脚有一个带条数的 Sources 按钮,点开是右侧「Sources」栏(右上角有关闭按钮,空的时候写「暂无来源」)。`http(s)` 来源可点击、新标签页打开,下面标出主机名。**如果这次回答存了长报告,Sources 里还会有一条「完整报告(可下载)」。**

**思考过程(Thinking)**:一步步的推理和工具调用轨迹在这里,标题「思考过程」,进行中时带一个「进行中」角标。入口是一条低调的灰色文字按钮「**查看思考过程 · {n} 步**」,渲染在**该条回复的正文上方**(不是下方),一条回复至多一个 —— 这条回复有过程步骤才出现;过程步骤不落库,刷新页面或换台设备打开这段对话后,之前的回复上就不再有这个入口。

- **它会在第一次出现过程步骤时自动弹开一次**(同时收起 Sources 腾地方)。你**手动关过一次之后就永久不再自动弹**(偏好记在浏览器本地)。
- **DevOps Agent 的调查步骤和普通模型推理共用这一个面板**;调查时面板头部会多一个「在 DevOps Agent 后台查看」。

### 4.8 长报告:在线看 + 下载

长内容不会糊进聊天。它会写到 S3,然后由**运行时**(不是模型)在回复末尾追加两个确定性链接:

- **🌐 在线查看完整报告(网页,链接约 7 天内有效)**
- **📥 下载完整报告(Markdown,链接约 12 小时)**

同一份报告也会作为一条「完整报告(可下载)」出现在 Sources 里。

> 在线链接走 CloudFront + OAC。**如果这套部署没配报告 CDN 域名**:走模型的那条路径会退到 12 小时预签名 URL;**直连(0 token)路径没有预签名兜底,会直接不给链接**。其中「约 7 天」不是 CDN 链接自己过期,而是桶上 `reports/` 前缀的生命周期规则到期删对象。

> ⚠️ 两个必须知道的点:
>
> 1. **落盘失败是静默的**。写 S3 出错时运行时只在自己日志里记一条 `report_link_skipped`,**不抛错、不在界面上提示** —— 表现就是这一轮回答正常结束,但**末尾没有链接**。想要报告又没看到链接,直接再要一次。
> 2. **在线链接本身不做鉴权**。拿到 URL 的人不需要登录 NotiOps 就能读到全文。所以**转发链接 = 交出报告内容**,请按内部资料对待。

### 4.9 停止生成

回答还在流的时候,**发送按钮会变成一个方形停止按钮**(提示语「停止生成」)。按下去:

- **只中断这一个会话**的流,别的会话照跑;
- 已经出来的部分**保留**,末尾补一句「_(已停止)_」;
- NotiOps 回答的那一轮会在**服务端真的停掉**(不再继续调模型、不再花 token),刷新后看到的也是「已停止」。代价是这个会话的下一句会慢一点(约 10 秒,服务要重新起一次);对话对象是 DevOps Agent / 深度调查那几轮只断开页面这一端。

### 4.10 回复页脚:谁答的、花了多少 token

每条回答都签了名:

| 页脚 | 含义 |
|---|---|
| `AWS Bedrock (<模型名>) · N tokens` | 走我们的 Bedrock 模型答的 |
| `Model gateway (<模型名>) · N tokens` | 管理员把 OpenAI 兼容网关排在模型来源第一,这一轮由网关答(见 §6.5) |
| `AWS DevOps Agent` | 由你自己的 DevOps Agent 答的(用量计在你的 DevOps Agent 上) |
| `NotiOps` | 确定性、不过模型的回答 |

- **token 数只在大于 0 时显示**,所以 0 token 的路径不会给你一个误导性的「0 tokens」。
- 页脚里**没有金额** —— 只有 token 数和模型签名。
- ⚠️ 例外:**在「调查」主题里,直连路径的回复刷新后会被签成 `AWS Bedrock (<模型名>)`**(落库时没带来源标记)。这是显示问题,不是真的走了模型 —— 那一轮确实 0 token。

### 4.11 会话管理

- 会话列表**按主题分组**:「已置顶」在最上面,然后是 通用 / 调查 / 成本 / 案例 / What's New,每组内按最近更新排序。**空的分组不渲染**,所以你看到的分组数会随使用变化。**没有「安全」分组** —— 2026-09-11 起它不再是对话主题,历史上标着「安全」的老会话会显示在「调查」组里(§2.4)。
- 每组可折叠,**折叠状态跨刷新保留**;至少有两个非空分组时,才出现「折叠全部 / 展开全部」。
- 每行的「…」菜单:**重命名**(就地编辑,`Enter` 保存,`Esc` 取消)、**置顶会话 / 取消置顶**、**删除**(会先弹「确定删除这个会话?」)。删除是**立即生效**的(不等 TTL),并且会连带清掉这条会话在 DevOps Agent 侧记的对话上下文。
- 行上还有两种小圆点:回答**正在流**时是「正在生成回复…」,你在别处时收到了新回复是「有新回复未读」。所以**发起一个长调查后可以放心切走**,回来能看到。
- 会话与消息带 **30 天 TTL**,但**每次在这个会话里说话都会刷新计时** —— 实际口径是「**闲置 30 天后自动删除,一直在用就一直保留**」。天数由部署侧的 `WEB_CHAT_TTL_DAYS` 决定,用户改不了,**到期前没有提醒**。

### 4.12 语言与外观

见 §1.2。两条容易被问到的:界面**默认英文**;界面语言**不决定**回答语言,你用什么语言问它就用什么语言答。

## 5. Skills(自建技能)

### 5.1 它解决什么问题

Skill 就是把「我们团队查 RDS 一定要先看这四个指标、再对一遍这份规范、最后按这个格式出结论」这类**你脑子里的流程**写下来,交给 NotiOps 执行。页面上的话是:「把你的流程、团队规范和专业知识教给 NotiOps —— 让它按你的方式做事。」

> **Skills 的增删改查只在 Web Chat 有。** IM 侧的 skill **管理**命令已于 2026-09-06 整体退役 —— 在飞书 / Slack / 钉钉里打 `/skills` 现在返回 `/help` 菜单(0 token)。但 IM 端的**使用**还在:`/agent notiops` 提问时照样会注入 Skills(两边共用同一份 S3 存储)。区别是 IM 路径注入 Skill 目录时**不带相关性闸门**,Web 端是每轮按你的问题筛。

> ⚠️ **Skills 是权限门控的。** 需要 `nav:skills` 才看得到这个入口;增删改 / 导入 / 回滚 / 发布到 DevOps Agent 各自还要 `action:skills:edit` / `:import` / `:rollback` / `:devops-agent`。6 个预置角色里**只有管理员和「开发者」**拿到 `nav:skills` —— `role:viewer`(默认映射给 Cognito `member` / `read-only` 组)、`role:finops`、`role:support`、`role:service-manager` 都看不到。**只授 `action:skills:*` 而不授 `nav:skills` 是不通的**(连列表都拉不到)。侧栏「更多」里找不到「技能」(英文界面 Skills),先去问管理员在「更多 → 管理 → 访问控制」里加。

### 5.2 开箱就有 12 个预置 Skill

新部署第一次列 Skills 时,**12 个官方 Skill 会自动种进存储**(作者标记为 `notiops-system`),不需要管理员做任何动作:

`aws-health-events`、`aws-well-architected-review-devops`、`cost-spike-triage`、`cost-usage-analysis`、`eks-operation-review`、`idle-resource-scan`、`rds-health-review`、`security-posture-review`、`service-quota-check`、`sp-ri-coverage-analysis`、`support-case-history-rca`、`whats-new-report`

列表把「**预置 Skills**」和「**我的 Skills**」分开,每张卡片打 **预置** 或 **自建** 标签,支持按 名称 / ID / 说明 搜索,以及「最近更新 / 按名称」排序。

> ⚠️ **预置 Skill 不要就地长期改。** 预置 Skill(作者 `notiops-system`)的正文由 NotiOps 维护:你直接编辑它的正文,**只在下一次播种之前有效** —— 下一次容器播种(或管理员手动重播种)会用打包内容覆盖回官方版本,你的改动**静默丢失**。同理,你硬删掉的预置 Skill 也会在下一次冷启动时被重新创建出来。
>
> **要长期定制,请复制成一个新的自建 Skill(换一个 Skill ID)。**
>
> ⚠️ 还有一个连带坑:**中文界面下编辑预置 Skill,编辑器加载的是中文正文,保存会把中文正文写进主正文。** 叠加上面那条覆盖,表象就是「改完生效、过一阵变回英文原版」。建议在英文界面编辑,或者干脆新建一个。

### 5.3 两种调用方式

**① 明确指定** —— 打 `/`,从菜单里选(§4.4)。选中后它把整份 Skill 正文按你提问的语言注入进去。Skill 如果带 `references/` 参考文件,这些文件会作为一份**按需清单**给模型,它可以用 `read_skill_reference` 去取 —— 这个读取被限制在**该 Skill 声明的文件允许清单**内、**只允许文档类扩展名**、单文件 ≤256 KB,并且**禁止路径穿越、禁止脚本、禁止跨 Skill 读取**。

**② 自然语言命中** —— 这条路由被一道**代码级关键词闸门**保护着(不是靠 prompt 叮嘱):命中 `skill_id` 或名称算相关;只在说明里命中的,需要**去掉中英停用词后有 ≥2 个不同的重叠词**(英文词 ≥3 字符 + 中文 2-gram)。比的是**你这一句的原话**;预置 Skill 的中文名称和说明也参与比对,所以用中文问(如「帮我做一次 RDS 健康检查」)一样能命中。**一个都不相关时,Skill 目录根本不会注入给模型** —— 所以误触发是**不可能**,而不是「不鼓励」。

> 2026-10-23 修正:此前闸门拿去比的是系统拼过语言 / 日期指令的那一整段,里面的通用词让几乎所有问题都过闸(问「What is Amazon S3?」时 11 个预置 Skill 有 10 个被注入)。现在改成比原话,无关问题不再注入。

### 5.4 自己写一个 / 用 zip 导入

- **新建 Skill**:直接在页面里写(名称 + 说明 + 正文)。
- **上传 zip**:只接受 `.zip`,支持 Claude / Agent-Skills 格式。`SKILL.md` 可以在任意层级,必须在 frontmatter 里有 `name` + `description`,正文 ≥20 字符。`references/`、`assets/` 只保留文档类扩展名(md/txt/json/yaml/csv/tsv/pdf/图片)。macOS 的 `__MACOSX/` `._` 噪音会被忽略。
- ⚠️ **`scripts/` 和可执行扩展名会被静默剥掉**:导入照样成功,但**界面只显示「已导入」,不会逐条告诉你剥了哪些** —— 想确认就自己对一遍文件清单。
- 限额:**界面上传前就拒 >6 MB**(这是你能看到的那个数);服务端还有 >10 MB 的 zip、>2000 个条目、单文件 >8 MB、解压后总量 >32 MB 四道上限,界面**不提示**,撞到只会看到一条后端报错。

> Skill 本质上就是部署时建的那个数据桶里的文件:`skills/<id>/meta.json` + `versions/<版本>.md`(预置 Skill 的中文正文是 `versions/<版本>.zh.md`)+ `files/` 放参考件。**直接往桶里放一个格式正确的 Skill,它就会出现,不用重新部署。**

### 5.5 版本历史与回滚

每个 Skill 都有**版本历史**,可以「**用此版本运行**」或「**设为当前版本**」回滚。编辑 / 导入 / 回滚是**三个独立鉴权的动作**,管理员可以分开授权。

### 5.6 发布到 DevOps Agent

「**发布到 DevOps Agent**」把这个 Skill 装进一个 DevOps Agent 的 Agent Space(本账号或成员账号)。发布后卡片上出现「已发布 ×N」的小标,支持**重新发布**和**移除**。**只上传文档,不含脚本**,只读边界不受影响。没有已接入的 Agent Space 时,它会让你先去「更多 → 管理 → 账户」接入。

- 发布时会在 Skill 的描述末尾加一句触发说明(`NOTIOPS_SKILL:<Skill ID>`)。DevOps Agent 是按任务描述自己挑 Skill 的,任务里带上同一个标记,它才能稳定地选中这一份。只改发过去的那一份,你写的描述不变。
- 打开发布对话框时会**回查**每个 Agent Space 里这份 Skill 是否还在,并如实标出:
  - **装的不是最新版**:写明「里面是 vX,最新是 vY」。改过 Skill 之后不会自动重新发布,要点「重新发布」;卡片上的「已发布」也会带一个提示点。
  - **已经不在了**:比如在 DevOps Agent 控制台里被删了。不再显示「已发布」,重新发布即可。
  - **旧版本发布、没带触发标记**:提示重新发布一次。

**Skill + DevOps Agent 组合时,输入框会明确告诉你这一轮会发生哪一种**:

| 路径 | 行为 |
|---|---|
| **深度调查**(交棒给 DevOps Agent) | Skill **必须已发布**,否则这一轮不会被激活 |
| **两条直连路径** | Skill 正文**内联**进这一轮发过去的内容(**不需要发布**),但它的 `references/` 参考文件在这条路径上**取不到** |
| **深度调查 + 很长的 Skill** | 深度调查的描述上限是 10,000 字。正文放不下时:已发布的 Skill 改为**引用 Agent Space 里安装的那份**(用的是你发布时的版本);没发布的,这一轮**不发起调查**,并提示你先发布 |

> ⚠️ 这里发布的 Skill **不影响资源巡检的 AI 判读** —— 巡检用的是另一个专属 Agent Space,判读 Skill 随代码发布,刻意与调查隔离,避免互相误激活。

### 5.7 边界

- **不支持脚本**。Skill 是文档(说明书),不是可执行程序。
- 每个 Skill 都是**本地执行**的;发布到 DevOps Agent 只是额外解锁「深度调查」时的增强。老版本里那个 per-skill 的 `execution_mode`(local / devops-agent / both)设置**已经没有了**,现在由会话里的 DevOps Agent 开关决定。
- Skill 和 IM 端共用同一个 `skills/` 存储前缀。

---

### 5.8 定时任务

「**定时任务**」在侧栏「更多」里、排在「技能」后面。它按你设的频率,自动用一个 Skill 发起一次 DevOps Agent **深度调查**,跑完把结果写成一个会话并发一条站内通知。思路参考 Claude Code 的 scheduled tasks(原名 Routines)。

**谁能用**:看列表要 `nav:routines`;新建 / 编辑 / 删除 / 启停 / 立即运行要 `action:routines:manage`。两个都**默认只有管理员有**,因为定时任务按计划**无人值守**地用这套部署自己的权限发起调查,而深度调查按秒计费。要开放给别人,在「更多 → 管理 → 访问控制」里单独授予(它们不在 `action:skills:*` 里,「开发者」角色不会自动拿到)。

**新建一个**:点「新建定时任务」;或者在「技能」页一个已发布的 Skill 卡片上点时钟图标「定时运行」,新建框会预选这个 Skill。

| 字段 | 说明 |
|---|---|
| 名称 | 最多 80 字 |
| Skill | **只能选已发布到 DevOps Agent 的**(见 §5.6)。运行时 DevOps Agent 用的是 Agent Space 里**安装的那一份**,不是你最新改过的版本。两者不一致时下拉下面会提示「Agent Space 里装的是 vX,最新是 vY」,想用最新版就先重新发布 |
| 目标账号 | 只列这个 Skill 已发布到的账号 |
| 补充上下文 | 最多 2000 字,例如关注哪些资源、看多长时间、结论用什么语言。每次运行都会带上 |
| 频率 | 一次性 / 每小时 / 每天 / 工作日 / 每周(选星期几)/ 每月(选几号;小月没有这一天就在那个月最后一天跑)/ 自定义 cron(5 段数字:分 时 日 月 周,周日 = 0 或 7;不认 JAN / MON 这类名字) |
| 时区 | 默认是你浏览器的时区;夏令时自动处理 |
| 起止日期 | 可选 |

**限制**(参考 Claude Code 的做法,再加上成本控制):

- 两次运行之间**至少间隔 1 小时**;到点后 **5 分钟内**开始(后台每 5 分钟检查一次)。
- 启用中的任务**最多 20 个**。
- 定时调查**同时最多 2 个**:DevOps Agent 每个 Agent Space 默认同时只跑 3 个调查,留 1 个给你平时手动发起的深度调查。名额满了先排队,30 分钟内等不到,这一次就跳过。
- 同一个任务**上一次还在跑**,这一次就跳过,不排队。
- 后台停过一阵、错过了:只补跑最近那一次(6 小时以内的),更早的记成「已错过」。
- 「立即运行」每个任务**每小时最多 3 次**,不影响下一次的计划时间。
- **连续 3 次没成功会自动暂停**,并发一条通知。Skill 被删 / 从 DevOps Agent 撤下、目标账号停用、负责人的账号被删,这几种**第一次就暂停**。处理好之后点「启用」,启用前会再核一遍 Skill 是否还在。
- 不会自动重试失败的调查(每次都花钱)。

**结果在哪看**:

- **会话**:每次运行在**负责人**名下生成一个会话(「故障调查」主题,标题「⏰ 任务名 · 日期」),里面是这次发出去的完整描述和调查结论,可以接着追问。会话是按人存的:别人在运行记录里看得到这一次,但打不开这个会话。
- **站内通知**:每次运行一条「定时任务完成 / 没有成功」。收件箱是**整个部署共享**的,能看「通知」的人都看得到。这类卡片上没有「深入调查」(结果本来就是一次调查),有「查看报告」;负责人还有「打开会话」。
- **运行记录**:每个任务的「运行记录」里有每一次的结果(包括跳过的和原因)、耗时、**Skill 有没有被加载**。DevOps Agent 是按描述自己挑 Skill 的:我们在描述里带上触发标记,事后再核对它的执行记录;没确认加载时会写明「未确认加载」,那次的结论可能是 DevOps Agent 的通用分析。
- **报告**:HTML 报告和「调查过程」页**保留 30 天**(普通深度调查的报告是 7 天),之后链接失效。

**成本**:每次运行都是一次 DevOps Agent 深度调查,按 agent 实际工作的时间计费(单价以 AWS 官方定价为准),频率越高花费越多。界面里不做费用预估。

**总开关**:运维可以一条命令停掉所有定时任务的派发(进行中的照样收结果),命令见两份部署指南。

### 6.2 角色与权限

- 权限树是**卡片粒度**的:一个角色可以只拿到成本页里的某几张卡片。每个分组有一个「**整个**」勾选框(等于该子树全选),分组标题是**三态**的;被上层「整个」覆盖到的卡片会显示成**已勾选但不可点**。
- `role:admin` 那一行是**只读**的,改不了。
- **删除一个还在被用的角色**会被拒,返回 `role_in_use`。
- 「管理员」= Cognito 里 `admin` 组的成员,权限是 `*`。
- **6 个预置角色**:管理员、只读查看、FinOps、支持/运维、开发者、服务经理。要点(和 §2.10 一致):`nav:security`(安全态势看板)只有**支持/运维**和**只读查看**带(2026-09-11 补的);**没有任何**预置角色带 `nav:customize`;只有开发者带 `nav:skills`;巡检的四个动作权限(范围 / 定时 / 阈值 / 手动跑)预置角色一个都没有。
- ⚠️ 一个已知的粗糙处:界面上**管理员可以把「管理」页签本身授权给一个自定义角色**。授权前想清楚。

### 6.3 模块开关

「模块」页是**按页签**整体开 / 关(显示「已启用」/「已停用」),**它优先于个人权限** —— 关掉之后所有人都看不到。API 只接受页签级节点,并且拒绝改**常开**的(对话)和**仅管理员**的(管理)节点。

### 6.4 账户:跨账号从这里来

用户在顶栏能切到哪些账号,取决于这一页接入并启用了哪些成员账号。「成员账号接入」有两条路:多账号模式部署(方式 B 的 `./setup.sh --multi-account`,或方式 A 参数 `DeployMode=MultiAccount`)下,组织内的账号点**「一键接入」**(StackSets 下发),第二步 DevOps Agent 关联随后自动发起,没完成或失败了就点那一行的**「一键关联」**重试;其余情况用同页的**「手动接入账号」**:输入账号 ID →「生成链接」→ 让那个账号的管理员用**那个账号**登录部署 → 回填 Stack Outputs →「测试连接」→「保存并激活」。成员账号里的采集角色由模板一并创建,**不用手建**;它挂 AWS 托管的 `ReadOnlyAccess`,**默认还带开 / 回复 / 关闭 Support 工单的权限**(模板参数 `EnableSupportCaseWrite=false` 可关,关了才是纯只读)。完整步骤见 [DEPLOYMENT.md §0.1.1](DEPLOYMENT.md)。

在这一页**停用**一个成员账号,NotiOps 就不再进那个账号:顶栏切不到它,看板接口、对话(哪怕在问题里写出它的 12 位账号号)、开工单都会拒绝访问它。2026-10-23 之前,看板接口和对话这两处还会照样进去查(只有开工单那条路拦住了),现在一并拦住。

> ⚠️ **还没升到 v1.0.30 的一键部署(方式 A)多账号栈**,第二步会失败:成员账号里那个采集角色第一步已经建好,第二步又建一个同名的 → `EntityAlreadyExists` → 回滚。先把栈更新到当前版本(每次更新都会重跑下发 StackSet 的那一步,把成员 DevOps Agent StackSet 的 `CreateCollectionRole` 改成 `no`),再点「一键关联」;之前第二步失败过的账号,更新之后重点一次就行。怎么更新栈(以及更新前要知道的注意事项)见 [DEPLOYMENT_ONECLICK.md §5](DEPLOYMENT_ONECLICK.md)。

### 6.5 模型

用户模型菜单里的列表 = 这一页启用的集合。一个都不启用时,用户侧会明确提示「管理员尚未为 Web 对话启用任何模型…请联系管理员在「更多 → 管理 → 模型」中启用。」并且**发送按钮禁用**。

**模型来源**有三个:本账号 IAM、Bedrock API Key(用另一个账号的 Bedrock)、**OpenAI 兼容网关**(LiteLLM、New API 等,填一个公网 HTTPS 地址和 Key)。

- 来源可以拖动排序,**只用排在第一的那个**。它出错就直接报错,**不会自动换到下一个来源**。每个来源各记一个默认模型。
- 网关的地址和 Key 存在本部署账号的 Secrets Manager(`notiops/litellm-config`),Key 不会回显到页面上。网关地址只接受公网 HTTPS 地址;换了网关地址,原来的 Key 不会沿用,要重新填。「清除」只是写入空值,旧 Key 在 Secrets Manager 里作为上一个版本保留到下一次写入 —— 要彻底作废,请在网关那边吊销。
- 网关排第一时,网页对话、IM 里 `/agent notiops` 之后的提问(同一个 Agent)和后台任务(比如 AWS Health 事件的翻译)都用网关;后台任务这时读不到网关配置也不会悄悄改用 Bedrock,Health 事件改为按原文推送。只有 IM 机器人自己调用模型的功能(比如 IM 里的案例分析)始终用 Bedrock 来源(本账号 IAM 或 Bedrock API Key)。
- 保存时,服务端会用第一来源的默认模型当场试调一次(网关排第一时,IM 用的那个 Bedrock 来源也一起试)。确定是配置错了才拦下;临时故障照样保存,并给出提醒。
- 网关答的那一轮,回答末尾的署名是 `Model gateway (…)`(平时是 `AWS Bedrock (…)`)。网关调用失败时,回答里会说明是哪一类问题(连不上、Key 被拒、网关没配这个模型的上游凭据、模型名不对等),并指到这一页。

Claude Sonnet 5.5 / Opus 5.5 和 GPT-6 Sol 要部署账号接受过它们的 AWS Marketplace 协议;没接受时这一页该怎么勾见 §15 —— 只把 Claude Sonnet 5 / Opus 5 启用回去只修好 Web,IM 还得同时停用 5.5。

## 8. Web Chat 使用须知

### 8.1 只读边界是谁保证的

Web Chat 的只读是**四层**叠出来的,但**四层不是同等强度**:

1. **IAM 权限** —— **这是唯一的硬边界**。就算上面三层全被绕过,权限本身也不允许改你的资源:Web Chat 访问你账号用的角色对你的基础设施只读;NotiOps 自己的资源(表、桶等)之外,唯一的写权限是 AWS Support case 的建 / 回 / 关,而且要你确认后才执行(见本节末尾;成员账号的角色可用模板参数 `EnableSupportCaseWrite=false` 收成严格只读)。⚠️ 方式 A 的部署参数 `AgentReadOnlyAccess`(默认 Yes)只决定 agent **能读多宽**,不影响这条边界:Yes 给 agent 的角色挂上 AWS 托管的 `ReadOnlyAccess`;No 只留精选的几组只读授权(成本、日志、指标、RDS / EC2 describe 等),范围更窄。两种取值下,agent 的角色都没有改你基础设施的权限。
2. **工具层只读** —— 挂给模型的工具本身就只有 describe / get / list 这一类。
3. **命令级 denylist** —— 挡住那些「技术上算读、但不该读」的调用:`secretsmanager get-secret-value`、带 `--with-decryption` 的 `ssm get-parameter`、`kms decrypt`、`ecr get-login-password`。⚠️ **这一层只在「部署账号」那条通用只读查询路径上生效**(全局只读兜底 MCP 的 `call_aws`)。查**成员账号**时改走按角色 AssumeRole 的原生只读接口,那条路径只有**读动词前缀允许清单**、**不再叠加命令级 denylist**,靠成员账号自己的 IAM 角色兜底(它对你的基础设施只读)。
4. **只读 system prompt** —— 要求先证据后结论,**禁止输出任何变更命令**、禁止编造资源 ID,示例一律只给 `describe-*` / `get-*` / `list-*`。⚠️ 源码注释明确写了:**别高估这一层,它是纵深防御,不是安全边界**。第 2、4 两层同理。

> 残留的已知口子(设计上承认):`lambda get-function-configuration` 和 `ecs describe-task-definition` 属于合法只读,但它们的返回里会带出环境变量。别把敏感值放在这两个地方。

> IM 端默认的 DevOps Agent 直连是**另一套**保证方式(DevOps Agent 侧的只读 agent + 只读角色,NotiOps 侧再加一条变更措辞正则);切到 `/agent notiops` 之后,IM 走的就是上面这套(同一个 AgentCore Runtime、同一个只读角色,只挂 AWS 文档检索和只读查询这几个工具,`/web on` 之后再加联网搜索)。见 §9 的「这个『只读』是谁保证的」。

**唯一的例外是 AWS Support case 的写操作**(建案 / 回复 / 关闭),它被设计成:

- 模型的工具**只返回一个待确认动作**(`pending_user_confirmation`),外加一条明确指令「不要声称已经执行」—— 所以回答**不可能**谎称它已经做了;
- 真正的写由**服务端**用你确认过的参数执行,**大模型不在写路径上**;
- 写完**回读核实**并把 `verified` 结果显示给你。

### 8.2 它会出错,重要结论要核实

输入框下面那句「NotiOps 可能出错,重要结论请核实」不是免责套话:

- 成本深挖的洞察明确标着「**AI 洞察(请核对)**」,旁边就给你原始 CSV。
- 深度调查的结论是 DevOps Agent 的原文,**NotiOps 不做二次总结**,但它仍然是模型产物。
- 由你自己的 DevOps Agent 回答时,提示语会换成「DevOps Agent 可能出错,重要结论请核实」。

### 8.6 一键部署(方式 A)少哪些东西

方式 A 是最小底座,只装 Web Chat。相对完整部署(方式 B,`setup.sh`):

- **没有巡检** —— 侧栏「更多」里没有这一项(整个页签不下发);只有缓存着旧版前端或直接调接口时,才会看到「需要方式 B」的提示(见 §2.6)。
- **成本的「每日异常扫描」卡片是方式 B 独有的**;方式 A 下这张卡整块不出现(依赖的函数被硬编码为空)。注意这和成本仪表盘里那张「成本异常」不是一回事,后者两边都有。
- **成本深挖的 4 个场景在方式 A 下默认点了会失败** —— 它们依赖 Athena 上预置的具名查询,而这些查询是 NotiOps 建的 CUR 第一次就绪时才建出来的。方式 A 只有选了 `ProvisionCur=yes` 才有这一步,而且要等 AWS 首次交付 CUR(最长 24 小时)、再被每 4 小时一次的检查发现之后才能用;没选(包括只填 `CurTable` 接已有 CUR 的情况)就没有这一步,点了会报 `no_named_queries` / `named_query_not_found`,不是空表。
- **4 张 CUR 报表两条路径一样**:默认都不出现,接上成本 MCP server 才有。方式 A 的接法是填 `CurTable` / 选 `ProvisionCur=yes`(NotiOps 替你部一个),或填 `CostAgentMcpUrl` + `CostAgentFunctionArn`(指向你自己的),见 §2.3。
- **通知收件箱不过滤 NotiOps 自己的告警** —— 方式 A 的 CloudWatch 告警订阅规则里没有排除 `notiops-inspection-*` 这类自建告警,所以 NotiOps 自身的告警也会进你的收件箱。
- **成本仪表盘里那张「DevOps Agent 调用额度」卡片默认一直显示「未配置」** —— 它读的是 NotiOps 建的那份 CUR,方式 A 选了 `ProvisionCur=yes` 才有:首次交付就绪前显示「数据初始化中」,之后出真实数据。
- 默认关闭的 5 类通知事件源,方式 A 下要去 **EventBridge 控制台**手动启用对应规则(方式 B 可以在 `setup.sh` 上加参数)。
- **Skills 两条路径完全一致** —— 方式 A 不缺任何 Skills 能力,包括 12 个预置 Skill、自建、zip 导入、版本回滚。

> **`EnableDeepInvestigation`(默认 Yes)是方式 A 上的一个总开关**,一次管三件事:**深度调查**(0 token 直连)、**「DevOps 对话」**、**把 Skill 发布到 DevOps Agent**。关成 No,这三项一起没有。另外,在 **AWS DevOps Agent 还没开服的区域**,即使填了 Yes 也会被**静默跳过** —— 想区分「我自己关了」还是「区域不支持」,去看栈的 Outputs 里的 `DeepInvestigationStatus`。

### 8.8 回答卡住或中途出错时

- **「这个会话的上一轮还没结束」**:同一个会话同一时间只能跑一轮。上一轮还在等模型返回时(比如它回答到一半你刷新了页面),再发一句就会看到这条提示 —— 这一句**没有发出去**,也不会被自动重发。这时消息流末尾会出现一条等待提示,写着已经等了多久;上一轮结束后它的回答会**自动出现**,不用自己刷新。刷新页面后打开一个还在回答的会话,也会直接看到这条提示。不想等可以点输入框右下角的停止按钮停掉上一轮,或者**新建一个对话**接着问,新对话不受影响。
- **「回答在中途断了」**:回答写到一半出错了(比如模型迟迟不返回、连接被断开),上面那段**不完整**。按提示里的下一步做:一般是直接再发一次;如果是模型迟迟不返回,把问题拆小一点,或在输入框右下角换一个模型。
- **刚冒出来的一段乱码又消失了**:模型偶尔会把输出崩成乱码(中英碎片用 `-` 粘在一起,或者一长串重复的符号)。系统一看出来就停掉这一次、丢掉那段乱码(不写进对话记录),在「思考过程」里留一行「已丢弃,正在自动重试一次」,然后用同样的上下文重试 —— 重试那次的回答接着出现。重试也崩了,会提示你**在输入框右下角换一个模型**再问。
- 失败提示里写了「已自动重试」,说明系统确实替你重发过(只有服务还在启动这类错误会自动重发);没写就是没有重发过。

## 9. bot 是什么 / 不是什么

### bot 能做什么 ✅

| 类别 | 能力 | 用法 |
|---|---|---|
| **调查 AWS 资源** | 分析 CloudWatch 指标 / 日志 / 资源配置,找异常根因 | `@bot RDS my-db CPU 100% 怎么回事` |
| **管理 Support case** | 创建 / 列出 / 查看 / 回复 / **智能分析** / 关闭 AWS Support case | `@bot 帮我开个 case 处理 RDS 故障` / `@bot 分析 case 177968247000414` |
| **回答 AWS 概念问题** | 引用 AWS 官方文档解释概念、最佳实践、API 用法 | `@bot ALB 和 NLB 有什么区别` |
| **主动观察告警** | ⚠️ **本版本 IM 群里收不到**:实时告警推送没有接上推送目标(见 §14);这类事件在 Web 的「通知」里看 | — |
| **多 LLM 切换** | 对话对象是 NotiOps Agent 时(见 §15.5),在管理员启用的模型之间任意切换(默认 **Kimi K3**,另有 Grok 4.7、GLM 5.3、Claude Sonnet 5.5 / Opus 5.5、GPT-5.6 Terra、GPT-6 Sol;均经 Amazon Bedrock 访问),per-chat / per-DM 记忆偏好。管理员把 OpenAI 兼容网关排到模型来源第一时,这里的对话改由网关的默认模型回答,`@bot model` 切换不生效(见 §6.5) | `@bot model opus` / `@bot model claude` / `@bot model list` |
| **语言切换** | 中 / 英文切换,记住你的偏好 | `language zh` / `language en` / `请帮我切换到英文` |

### bot 不会做什么 ❌

> 这是产品级硬规则,**不是档位可调项**。

- ❌ **修改你的 AWS 环境**:不会重启 EC2、不会删 S3 对象、不会改 IAM 策略 —— 任何变更类请求都会被拒绝
- ❌ **替你执行 CLI 命令**:你问 "重启 i-0123",bot 会拒绝;你问 "怎么重启 i-0123",bot 会教你怎么做(教程视为只读)
- ❌ **绕过 IAM**:你能查到的资源 = 替你作答的那一方的角色能读的资源(默认是你的 AWS DevOps Agent 用的角色;`/agent notiops` 之后是 NotiOps AgentCore Runtime 的只读角色),bot 不会替你越权
- ❌ **存储敏感信息超过 7 天**:聊天历史 DDB TTL 7 天自动清理,locale 偏好 90 天。⚠️ 例外是深度调查的报告与 Trace 页面:它们存在数据桶的 `investigations/` 前缀下,**不会自动删除**,一直留到桶被删除(见 §19 Q3)

> **这个"只读"是谁保证的(2026-09-03 起口径变了,请照新的看)**:IM 侧的问答**默认直连
> AWS DevOps Agent**、NotiOps 自己不过 LLM(所以 0 token),这条路上
> **拒绝变更是由 DevOps Agent 侧 + 它使用的 IAM 角色(对你的基础设施只读)保证的** —— 不再是"NotiOps 先用
> 一次 LLM 判断你是不是想改东西"。发过 `/agent notiops` 的群 / DM,问题改由 Web Chat 那**同一个**
> AgentCore Runtime 用模型来答,只读靠的是它那一套:IAM 权限(硬边界,对你的基础设施只读)+ 只挂 AWS 文档检索和
> 只读查询的窄工具集(见 §8.1、§15.5)。两条路前面 NotiOps 侧都有一条**正则二道门**
> (`platforms/common/router.py`),用来拦明显的变更措辞与 prompt injection。
> 叠起来的实际效果:**变更类请求到不了执行**。唯一会写的是 AWS Support case(开 / 回复 / 关闭),

## 11. 调查 AWS 资源

### 11.1 标准调查流程

**明说要深挖**,bot 才会开一次深度调查 —— 用命令 `/调查`(`/investigate`),或者在话里带上「深度调查 / 深入排查 / 根因分析 / 深挖」这类说法(英文 deep dive / investigate / root cause / RCA 等)。⚠️ 命令前面那个斜杠**可以省**:消息的**第一个词**是 `调查` / `調查` / `排查` / `深度调查` / `investigate` / `inv` / `investigation`、后面跟着空格或标点时,同样按命令派发 —— 比如 `@NotiOps 排查 RDS 慢`、`@NotiOps inv rds slow` 会直接开一次深度调查,而 `@NotiOps 排查一下 RDS 慢`(词后面紧跟着别的字)不会:

```
@NotiOps 深度调查一下 IAD 的 i-0abc123def456 为什么 CPU 这么高
```

没有这类说法的普通问题(比如「帮我看下 IAD 的 i-0abc123def456 为什么 CPU 这么高」)**不会**开调查,而是直接交给这个群的对话对象回答(默认是你自己的 DevOps Agent,见 §13.4 / §15.5)。

bot 会:

1. **认出这是要深挖**(确定性的规则匹配,0 token,不调模型)
2. **直接派发**给 DevOps Agent —— 没有编辑表单,也不用再点确认;你那句话原样作为调查描述交过去,NotiOps 不改写、不总结
3. 回一张「**深度调查已发起**」卡片(见 §11.2),带一个去 DevOps Agent 后台看这次调查的按钮
4. 之后这张卡**约每分钟原地刷新一次**,把 DevOps Agent 的新进展追加上去(见 §11.3;钉钉的消息改不了,不刷新,见 §17.2)
5. 结束时这张卡的标题变成「✅ 调查已完成 · 用时 N 秒 · 报告见下方」(失败是「⚠️ 调查失败」),紧接着群里出一张**报告卡**(见 §11.4)。用时随问题复杂度和账号规模而变

### 11.2 「深度调查已发起」卡片

```
深度调查已发起
─────────────────────
✅ 已派发,DevOps Agent 正在调查中

⚡ 直连 DevOps Agent · 无模型消耗 · 账号: 111122223333(部署账号)

[ 🔬 查看本次调查 ]
```

- 按钮打开 DevOps Agent 后台里这次调查的页面;拿不到这次调查的深链时,换成「🌐 Operator 主页」。
- 落款写明这次调查查的是**哪个账号** —— 查错了账号的报告看起来和查对了一模一样,值得看一眼。
- **没有编辑表单**:NotiOps 不替你补问维度。想让 DevOps Agent 更快定位,**发的时候就写进去**:账号、Region、资源 ID / ARN、时间窗口,以及告警名或日志 / 错误片段。

### 11.3 进度卡片详解

进度不是另发一张卡,而是上面那张卡**原地刷新**(飞书 / Slack):

```
🔍 调查中 · 已用时 125 秒
─────────────────────
(DevOps Agent 调查日志里的新条目,一条条往下追加)

⚡ 直连 DevOps Agent · 无模型消耗 · 账号: 111122223333(部署账号)

[ 🔬 查看本次调查 ]
```

- 一个进度 Lambda **每分钟**去拉一次 DevOps Agent 的调查日志,有新条目就追加到这张卡上;还没有条目时正文是「⏳ Agent 正在分析问题、规划调查步骤…」。
- 卡上始终只有**一个**按钮(「🔬 查看本次调查」,拿不到深链时是「🌐 Operator 主页」),调查结束后仍可点。
- 结束时标题变成「✅ 调查已完成 · 用时 N 秒 · 报告见下方」或「⚠️ 调查失败 · 用时 N 秒」,报告卡随后单独发出(§11.4)。
- **钉钉上没有这张会刷新的卡**:钉钉的消息发出后改不了,回执里会明说「这条不会自动更新」;想看中间进展就点回执里的链接去 DevOps Agent 后台看,报告跑完照样自动投回这个会话(见 §17.2)。

### 11.4 报告卡片详解

调查结束后群里只出**一张**卡。顶部第一行就是你当初问的那句话 —— 同一个群里
并发跑了几个调查时,靠它区分哪张卡对应哪次调查:

```
✅ NotiOps 报告
─────────────────────
🎯 调查目标 · 为什么 EC2 i-0abc123def456 的 CPU 打满了
事件 · Investigation
状态 · COMPLETED    优先级 · P2
Task · abcdef0123456789
─────────────────────
## Summary
过去 1 小时 CPU 持续 95%+,主要进程 nginx + php-fpm。

## Root cause
应用层 CPU bound,nginx 配置 worker_connections=1024 不够用,
导致大量请求排队。
─────────────────────
[ 📊 查看完整报告 ]   [ 🔍 调查过程 Trace ]
[ 🆘 升级到 AWS Support ]

🔗 链接 7 天内有效 · 无需登录控制台即可访问
```

三颗按钮各去哪儿:

| 按钮 | 打开什么 | 要不要登录 |
|---|---|---|
| 📊 查看完整报告 | S3 上的完整报告页(Summary + Root cause 全文) | 不用 |
| 🔍 调查过程 Trace | 调查时间线:Agent 每一步查了什么、看到什么 | 不用 |
| 🆘 升级到 AWS Support | 拿这份报告开一个 Support case(已关联 case 时换成「同步到 case」) | 要 |

> 报告卡上**没有**「🔬 查看本次调查」(DevOps Agent 控制台深链)。前两颗按钮
> 打开的都是免登录的链接,**约 7 天内有效**:页面放在报告 CDN(CloudFront)后面,
> 7 天后桶上的生命周期规则删掉对象,链接随之失效,要留档就在这之前把页面存下来。
> 少数部署没有配报告 CDN(或那一次副本没写成)时,链接退回 S3 预签名 URL,
> 只在**数小时内有效(最长约 12 小时)**—— 卡片底下那行会如实写成这一句。
> 控制台深链则必须先登录 AWS 控制台,两种混在一排里,底下那行说明就只能同时写
> 「无需登录」和「需要登录」。想看控制台原始页面的话(包括这两个链接失效以后),
> 进度卡上那颗「🔬 查看本次调查」还在(见 §11.3),调查结束后仍可点。

**卡片正文是完整报告的开头一段。** 报告长过卡片能放的量时,正文末尾会多一行
「⚠️ 卡片仅展示报告的开头部分 · 完整内容见「📊 查看完整报告」」—— 那颗按钮里
的内容**没有**被裁过。反过来,没有这行提醒就说明你在卡上看到的就是全文。

> 🔴 v1.0.22 之前这里是**两张**卡(「📝 Report Summary」+「✅ NotiOps 报告」),
> 且前一张的正文由一次 1024 token 预算的大模型摘要生成 —— 推理模型的 thinking
> token 会吃光那点预算,于是经常只剩一句「报告因 token 限制被截断」,偶尔一个字
> 都没有。现在合成一张、正文直接取 DevOps Agent 的原文,**整条深度调查链路 0
> token**。

### 11.5 调查类样例

| 你想问 | 推荐说法 |
|---|---|
| 某个 EC2 CPU 高 | `i-0abc123def456 在 ap-east-1, 最近 1 小时 CPU 100%` |
| RDS 慢查询 | `RDS my-db 慢查询多, 看下原因` |
| Lambda 报错 | `lambda function-foo 大量 error, 看 cloudwatch logs` |
| ALB 5xx 升高 | `ALB my-alb 503 持续报错 30 分钟` |
| S3 bucket 突然变大 | `s3://my-bucket 上周空间从 100GB 涨到 1TB, 查异常` |
| EKS pod CrashLoop | `eks 集群 prod-cluster pod xyz 一直 CrashLoopBackOff` |
| 跨服务依赖 | `从 ALB 到 EKS 到 RDS 全链路 timeout, 帮我串一下` |

> 💡 **提示**:上表的说法前面加上 `/调查`(斜杠可省,见 §11.1;或在话里带上「深入排查」「根因分析」这类说法)才会开**深度调查**(§11.1);不加的话,bot 把它当普通问题直接回答(默认由你自己的 DevOps Agent 答,它同样会去读指标和日志)。两种情况下 NotiOps 都**不会**替你追问维度,所以发的时候就把资源 ID / region / 时间窗口带上,定位更快。

## 12. AWS Support case 管理

bot 不仅会调查,还能帮你**管理 AWS Support case**(创建 / 查看 / 回复 / 关闭),省掉每次切控制台。

### 12.1 创建 case

```
@NotiOps 创建一个 case 处理 RDS my-db 频繁重启
```

bot 会出一张**创建 case 的表单**:飞书是发在会话里的一张**卡片表单**;Slack 是一个 modal(从 @ 提问进来时先回一颗「🆘 打开创建表单」按钮,点一下才弹出)。可以填:

| 字段 | 说明 |
|---|---|
| **开到哪个账号** | 只在这套部署有 ≥2 个账号可选时出现,默认选中这个会话当前的账号(`/account`) |
| **Subject** | 从你那句话里去掉「开案例 / 创建 case」这类说法后**预填**(确定性规则,不调模型),可改 |
| **Body** | 详细描述(可粘贴原始日志) |
| **Severity** | Low / Normal / High / Urgent / Critical |
| **Language** | English / Japanese / Chinese 等(case 在 AWS Support 里的对话语言) |
| **Contact** | 可选,联系方式 |

Slack 的 modal 里还多「服务名称 / 类别 / 案例类型」这几项;飞书卡片不问它们,提交时由 bot 自动判断涉及的服务与类别。

填完提交,bot 会调 AWS Support API 创 case,完成后给你 case ID(`12345...`)。

> 🔥 **创建 + 直接派发调查**:飞书卡片底部是两颗提交按钮 ——「🚀 仅创建 Case」和「🤖 创建 + 启动 Agent 调查」;Slack 的 modal 只能有一个提交按钮,所以改成表单里的二选一(默认选中「🤖 创建 Case + 同时启动 Agent 调查(推荐)」)。选后者会先创 case,再以"调查这个 case 的根因"的角度自动派发一次 DevOps Agent 调查。等于一次操作完成 "提单 + 启动自查"。

> 📌 **钉钉端形态不同**:钉钉没有原生 modal,也没有按钮回调,所以同样的信息走的是"bot 回一张纯文本模版 → 你整段复制改完发回来 → 回一句「确认」"。模版是六行(问题描述 / 严重等级 / 语言 / 案例类型 / 涉及服务 / 标题),只有问题描述必填;建出来的 case 与这里完全一样。详见 §17.2。

### 12.2 列出我的 case

```
@bot 我的 case
@bot 列出我的 case
```

bot 会列出这个账号最近 90 天里新建的 **5 条** case(**不限状态**,新的在前),每条带状态、severity 和创建日期,下面有「💬 详情」「✏️ 回复」等按钮。要按状态看,点列表底部那一排筛选按钮:👤 待我处理 / 🔵 未解决 / 🛠️ 处理中 / ✅ 已解决。⚠️ 状态**写在话里不会筛选**,只能用这排按钮;钉钉的消息没有按钮,要按状态看就点消息末尾的 AWS 控制台链接。

### 12.3 查看某个 case

```
@bot case 177968247000414
@bot 查看 case 177968247000414
@bot case 177968247000414 怎么样了
```

bot 返回 case 详情 + 最新回复历史。

### 12.4 给 case 加回复

```
@bot 回复 case 177968247000414 已经把 RDS 升到 r5.large 不再重启
@bot reply to case 177968247000414 fixed by upgrading instance class
```

> 必须带上**完整的** case ID(AWS 给的那一长串数字;不到 6 位的数字不会被当成 case ID),否则 bot 会先列出最近的 case 让你选一个。
>
> 🔒 **这样说的回复不会直接发出**:bot 把它从你那句话里识别出的正文放进回复表单(飞书 / Slack;钉钉是一条确认说明),你核对、需要的话改一改,点「发送」才写进工单。想一步到位,用显式命令 `/回复案例 177968247000414 <正文>`(英文 `/reply-case`)—— 正文写在命令里,那句命令本身就是确认,会直接发出。**开头的斜杠不能省**:不带斜杠的「回复案例 177968247000414 …」读起来和一句话没有区别,也会先放进回复表单等你确认。

### 12.5 让 bot 智能分析 case(LLM 复盘 + 下一步建议)

需要让 LLM 通读 case 全部交流并给出"现在该怎么办":

```
@bot 分析 case 177968247000414
@bot 总结 case 177968247000414
@bot 案例分析 177968247000414
@bot 帮我分析 case 177968247000414 是什么原因
@bot 分析 case 177968247000414 该怎么回
@bot summarize case 177968247000414
@bot analyze case 177968247000414
@bot analyze case 177968247000414 — what's wrong with it
```

> 「复盘 case …」「帮我看 case …」「case … 应该回什么」这类说法**不会**触发智能分析,只会打开这个 case 的详情 —— 请用上面这几种说法,并带上完整的 case ID。「怎么回复 case …」这类问法会被认成**回复**:bot 不会发出,而是把识别出的那段话放进回复表单等你确认(见 §12.4)—— 要问该怎么回,用上面「分析 case … 该怎么回」的说法。

bot 会先发"正在分析 case xxx…"提示,5-15 秒后返回**紫色智能分析卡片**,包含 6 个 section:

| Section | 内容 |
|---|---|
| 📝 **现状摘要** | 一句话症状定性 |
| 🔍 **根因推断** | 根据 case 已有信息的最佳判断,证据不足时会明确说"evidence insufficient" |
| 🛠 **AWS 工程师进展** | 工程师当前进展评估(已经回了什么 / 在等什么) |
| ✅ **建议下一步** | 用户应该做的具体动作(优先级排序) |
| 📋 **应补充给 AWS 的信息** | 用户该向 AWS 提供哪些数据 / 日志 / 配置 |
| ✉️ **建议回复模板**(可选) | 一段 ≤300 字的回复草稿,用户可直接复制 |

底部 2 个按钮:**💬 回复 case** / **📋 查看完整 case**。

> ⚠️ **零变更承诺仍生效**:LLM 永远不会建议"删 / 停 / 改"这种变更命令。如果只能通过变更才能解决,bot 会让你**人工执行**,不会替你做。

### 12.6 关闭 case

```
@bot 关闭 case 177968247000414
@bot resolve case 177968247000414
@bot 177968247000414 已解决
```

## 13. 问 AWS 概念 / 文档

> ℹ️ 这不需要任何部署开关。谁来回答取决于这个群的**对话对象**(§15.5):默认由你自己的 DevOps Agent 直连作答;切到 NotiOps Agent(`@bot agent notiops`)之后,才由 NotiOps 检索 AWS 官方文档、用模型回答。

### 13.1 怎么问

直接 @ bot 提问就行 —— 只要话里没有「深度调查 / 根因分析」这类要深挖的说法、第一个词也不是「调查 / 排查」这类命令词,它就当普通问题回答,不会开调查(见 §13.4):

```
@bot ALB 和 NLB 有什么区别
@bot Lambda cold start 是什么意思
@bot CloudWatch alarm 的 evaluation period 是怎么算的
@bot 怎么给 IAM role 加 cross-account trust
```

### 13.2 回答样式

对话对象是 **NotiOps Agent**(`@bot agent notiops`,见 §15.5)时,bot 调用 **AWS Knowledge MCP** 检索官方文档,再用本群当前的对话模型(默认 **Kimi K3**,见 §15)回答,**附带可验证的来源**(样例见下);默认的 **DevOps Agent 直连**则由你自己的 DevOps Agent 回答(NotiOps 侧 0 token,不带来源块)。

```
NotiOps Agent 回答
─────────────────────
ALB (Application Load Balancer) 工作在 OSI Layer 7,理解 HTTP/HTTPS 协议,
能基于 host / path / header 路由请求。NLB (Network Load Balancer) 工作在
Layer 4,只看 TCP/UDP,不解析应用层。

主要差异:
1. **协议**:ALB 解析 HTTP,NLB 不解析
2. **健康检查**:ALB 可以检查 path,NLB 只 TCP
3. **延迟**:NLB 更低(因为不解析)
4. **静态 IP**:NLB 支持,ALB 不支持
5. **WebSocket**:ALB 原生支持
─────────────────────
**过程**

- (这一轮做过的检索 / 查询步骤,每步一行,只留最近 8 行)
─────────────────────
**参考来源**

- [Application Load Balancer overview](https://docs.aws.amazon.com/...)
- [Network Load Balancer overview](https://docs.aws.amazon.com/...)
- [Choose between ALB and NLB](https://docs.aws.amazon.com/...)
─────────────────────
Agent: NotiOps | Model: global.moonshotai.kimi-k3 · 账号: 111122223333(部署账号)
```

**重点**:
- **「参考来源」** = 这一轮检索(AWS 文档检索;`/web on` 之后还有联网搜索)实际带回的出处,不是凭空编的;最多列 5 条,只出现在答完的终版卡上
- **「过程」** = 这一轮做过的步骤,让你看到它查了什么;只留最近 8 行
- **落款** `Agent: NotiOps | Model: …`(模型 id 跟随本群当前模型;bot 确认不了这一轮实际是哪个模型答的时,只写 `Agent: NotiOps`,不报模型)= 标明这是 NotiOps Agent 用模型生成的回答,不是固化的"标准答案";后面那段是这一轮基于哪个账号
- 默认的 DevOps Agent 直连那张卡标题是「DevOps Agent 回答」,**没有**「参考来源」,落款是「⚡ 直连 DevOps Agent · 无模型消耗 · 账号: …」

### 13.3 概念问题样例

| 类别 | 样例 |
|---|---|
| **服务对比** | `ECS vs EKS 怎么选`、`SQS standard 和 FIFO 区别` |
| **API 用法** | `S3 multipart upload 最大可以多大`、`Lambda 并发限制怎么配` |
| **最佳实践** | `IAM role chaining 怎么避免`、`VPC peering 和 transit gateway 怎么选` |
| **错误解读** | `什么是 Throttling exception`、`UnauthorizedOperation 通常什么原因` |
| **配置选项** | `KMS multi-region key 是什么`、`RDS multi-AZ vs read replica` |

### 13.4 何时改派调查 vs 概念问答

bot **不猜**你的意图,只按下面这套字面规则判断:

| 你的话 | bot 怎么处理 |
|---|---|
| `什么是 ALB` | 普通问答 |
| `查 ALB my-alb 的 5xx` | 普通问答 —— 「查」不算要深挖,带了资源名也一样 |
| `排查一下 RDS 慢` | 普通问答 —— 「排查」后面紧跟着别的字,不算命令 |
| `Lambda cold start 怎么解决` | 普通问答 |
| `深入排查一下 lambda foo 的 cold start` / `/调查 lambda foo cold start 严重` | 派发深度调查(§11) |
| `排查 RDS 慢` / `调查 RDS 慢` / `inv rds slow` | 派发深度调查 —— 第一个词是命令词、后面跟着空格,等于省了斜杠的 `/调查` |

判断依据:**只有明说要深挖**才派发深度调查 —— 用 `/调查` / `/investigate` 命令(斜杠可省:消息第一个词是 `调查` / `調查` / `排查` / `深度调查` / `investigate` / `inv` / `investigation`、后面跟空格或标点),或者话里任何位置带上「深度调查 / 深入排查 / 根因分析 / 深挖」、deep dive / investigate / root cause / RCA 这类说法;带不带资源 ID / region / 时间窗口都不影响。其余一律当普通问题,交给这个群的对话对象回答(默认是你自己的 DevOps Agent,§15.5)—— 它照样能去读指标、日志和配置。这一步是确定性的规则匹配,不调模型、0 token。⚠️ 规则只看字面:「什么是根因分析」「what is RCA」这种概念问题也会派一次调查 —— 想问概念,措辞里别带这几个词。

## 14. 被动场景:收到主动告警卡片

> ⚠️ **本版本 IM 群里收不到这类实时告警卡片。** 推送 Lambda(`notiops-push-handler`)只有 `setup.sh` 部署才建(一键部署根本不建这个函数,也不建 `notiops-push-*` 规则);它发不发只看它自己的环境变量(`PUSH_TARGET_CHAT_ID` 等),而 `setup.sh` 不设这些变量 —— 所以即使把 `notiops-push-*` 规则打开,每个事件也只在日志里记一行「Push disabled」就返回(飞书的 `notify_chat_ids`、钉钉的 `webhook_url` 都管不到它)。这类事件现在请在 Web Chat 左侧「**通知**」里看(两条部署路径都有,默认收 5 类,见 §2.1)。IM 群里**会**收到的主动消息只有 `setup.sh` 部署下飞书群的「每日运维通知」和 Health(PHD)事件转发,见 [im-bot-interaction.md](im-bot-interaction.md) 的「定时日报推送」一节。下面 14.1 ~ 14.3 描述的是这条推送链路本身的设计(代码在,只是本版本没有接上推送目标)。

### 14.1 告警自动调查的工作方式

推送链路接通之后,bot 会监听 5 类事件(每类一条 `notiops-push-<源>` 规则,建出来都是关的):

| 事件源 | 触发条件 |
|---|---|
| CloudWatch Alarm | Alarm 状态变 ALARM |
| AWS Backup | Backup job FAILED / EXPIRED / ABORTED |
| GuardDuty | 新 finding(默认严重性 ≥ 7) |
| Cost Anomaly | 异常费用变化 |
| Trusted Advisor | check status 变 ERROR |

> AWS Health 不在这张表里:它没有对应的 `notiops-push-*` 规则。`setup.sh` 部署下它走的是另一条 PHD 转发(投飞书群),见本节开头。

**事件触发后**:

1. push handler Lambda 收到 EventBridge 事件
2. 5 分钟去重(同一资源 5 分钟内只调查一次)
3. **自动派发** DevOps Agent 调查 — 调查请求文本由 bot 根据事件 normalize 生成
4. 群里收到 **⚠️ 主动观察:<事件简要>** 头部卡片
5. 跟手动调查一样的进度卡 → 报告卡片流程

### 14.2 告警卡片样例

```
⚠️ 主动观察 · CloudWatch Alarm
─────────────────────
告警名:high-cpu-prod-rds
状态:ALARM
原因:Threshold Crossed: 1 datapoint [98.5] > 85.0

DevOps Agent 已自动启动调查...
```

后续就和 §11 的报告卡一样。

### 14.3 静默期间

群里某个事件源太吵?管理员可以单独关闭(disable 对应的 EventBridge 规则,瞬时生效、不用重新部署):

```bash
# 关 GuardDuty 推送(管理员侧)
aws events disable-rule --name notiops-push-guardduty --region <部署区域>
```

详细配置选项见 [DEPLOYMENT.md §7](DEPLOYMENT.md#7-开启--调整-push-模式)。

## 15. 模型与对话对象

> 这一节其实是**两件事**:**15.1 ~ 15.4 讲「用哪个模型」**(`model`),**15.5 讲「这一句交给谁来答」**(`agent`)。两者不能混:模型**只在对话对象是 NotiOps Agent 时才有意义** —— DevOps Agent 那条路不经过我们的 Bedrock 模型。

bot 支持的别名 = 管理员在模型目录里勾选的 IM 启用集(下表列出常用几个),任何用户都可以在群里 / DM 里**随时切换**(无 admin 控制);完整清单用 `@bot model list` 现场查:

| alias | 模型 | 说明 |
|---|---|---|
| `kimi` | **Kimi K3** | **默认值**(模型目录 `default_model`)。Bedrock Converse;不支持显式提示缓存(内部实测隐式缓存会生效) |
| `claude` | **Claude Sonnet 5.5** | 内部测试中工具调用较稳、中英文都好;支持提示缓存 |
| `opus` | **Claude Opus 5.5** | 推理最强,适合深度分析 / 复杂根因;支持提示缓存 |
| `grok` | **Grok 4.7** | Bedrock Converse;⚠️ 不支持显式提示缓存,长会话的 input 成本比 Claude 高 |
| `gpt` | **GPT-5.6 Terra**(实验性)| 走 Bedrock Mantle Responses API,工具调用稳定性弱于上面几个,建议仅作尝鲜 |
| `gpt_sol` | **GPT-6 Sol** | 走 Bedrock Converse(global 跨区推理 profile,跟 Kimi / Grok 同一条路),不经 Mantle,也不用像 GPT-5.6 那样单独调 `us-east-2` |

> ⚠️ **`@bot model list` 里还会列出 `gpt_luna`(GPT-5.6 Luna,出厂只对 IM 启用),眼下别选它。** NotiOps Agent 那一侧不认这个别名:切过去之后每一句其实都由默认模型(没改过时是 Kimi K3)回答,卡片落款只写 `Agent: NotiOps`、不报模型(bot 确认不了是哪个模型答的)。管理员可以在「更多 → 管理 → 模型」里把它停用,`@bot model list` 里就不再出现;已经钉在它上面的群 / DM 会回落到默认模型。

> ⚠️ **Claude Sonnet 5.5 / Opus 5.5(`claude` / `opus`)和 GPT-6 Sol(`gpt_sol`)要求部署账号接受一次它们的 AWS Marketplace 协议。** 没接受时,用这几个别名的每一句都会失败(NotiOps Agent 回「模型调用被拒绝」)—— 也包括升级前就设成 `claude` / `opus` / `gpt_sol` 的群 / DM(那时它们还是 Claude Sonnet 5 / Opus 5 / GPT-5.6 Sol):只要没人在「更多 → 管理 → 模型」里保存过,升级后这几个别名就指向上表的新版本,没人去切也照样开始失败。每个没接受协议的模型,管理员各选一种处理:
>
> - **在部署账号里把它的协议接受一次**,对应的别名就照常可用。
> - **暂不接受 Claude 5.5**:在 Web 的「更多 → 管理 → 模型」里把 **Claude Sonnet 5** / **Claude Opus 5** 重新启用,**同时停用** **Claude Sonnet 5.5** / **Claude Opus 5.5**,再告诉 IM 用户改用 `@bot model claude-sonnet-5` / `@bot model claude-opus-5`。只启用 5、不停用 5.5,**只修好了 Web** —— IM 的 `claude` / `opus` 仍然指向 5.5。停用 5.5 之后,已经钉在 `claude` / `opus` 上的群 / DM 会回落到默认模型,再发 `@bot model claude` 会提示未知模型并列出可选项。
> - **暂不接受 GPT-6 Sol**:停用 **GPT-6 Sol**,钉在 `gpt_sol` 上的群 / DM 同样回落到默认模型。

> ⚠️ **GPT-5.6 当前为实验性档位**。GPT 在 tool-use 场景下偶发把 OpenAI 内部协议片段或低质 token 输出到回复中,概率高于 Claude / Kimi,所以建议日常使用默认的 `kimi` 或 `claude`,把 GPT 当作"我想试试 Open AI 模型"的尝鲜选项。
>
> 注:默认所有模型均经 Amazon Bedrock 访问(托管的安全、合规监控与成本控制);管理员把 OpenAI 兼容网关排到模型来源第一时,对话与后台任务改走该网关及其上游供应商(见 §6.5)。本项目为示例代码(sample code),用于学习/参考,非生产就绪;正式使用前请按贵组织的安全、合规要求自行完成充分测试与加固。

### 15.1 命令一览

```
@bot model              # 查看本群 / 本 DM 当前模型
@bot model list         # 列出所有可用别名
@bot model opus         # 切到 Claude Opus 5.5(整个群从此用 Opus)
@bot model claude       # 切到 Claude Sonnet 5.5
@bot model default      # 清除偏好,回到管理员设的 default_model(没改过时是 Kimi K3)
```

### 15.2 切换的范围

- 在**群里**发命令 → **整个群**之后都用这个模型(包括别人的提问)
- 在**私聊**发命令 → **只影响你的 DM**,不影响群

也就是说:日常的群用默认的 `kimi`,专做深度分析 / 复杂根因的群可以切到 `opus`,**同一个 bot 部署服务多个场景**。

### 15.3 切到 GPT 的注意事项(实验性)

GPT-5.6 Terra(`gpt`)走 **Bedrock Mantle Responses API**(OpenAI 兼容协议),跟 Claude / Kimi / Grok 在 Bedrock InvokeModel / Converse 上不一样(`gpt_sol` 是 GPT-6 Sol,走的是 Converse,下面这几条说的都不是它):

- **稳定性**:在 tool-use(概念问答 / 只读查询)场景下,GPT-5.6 偶发会把 OpenAI 内部协议片段(`to=functions.<tool>`)或低质 token 写到回复里,出"半灰"回复的概率高于 Claude / Kimi。**正式使用时优先默认的 `kimi` 或 `claude`**,GPT 仅作为尝鲜或对比档位。
- **跨 region 调用**:GPT-5.6 的请求发往模型目录里该条目登记的区域(出厂是 `us-east-2`),跟你部署在哪个区无关。部署区域不是 `us-east-2` 时,选 `gpt` 就会发起一次跨 region HTTPS 调用 —— 从 `us-east-1` 发起时延迟比 Claude / Kimi 高 ~50ms,但不影响功能。
- **区域**:部署没有暴露改它的参数;Web 的「更多 → 管理 → 模型」里点该模型的 ⓘ 能看到这个区域,但只能看、不能改。
- **Reasoning effort**:GPT-5.x 有显式的"思考深度"档位;NotiOps 不设置它(用服务端默认),部署和界面也都没有改它的入口。
- **工具调用**:跟 Claude / Kimi 用的是同一组只读工具(AWS 文档检索、AWS 只读查询,`/web on` 之后再加联网搜索),协议自动翻译。

### 15.4 偏好的生效层级

```
1. 群级偏好(@bot model X 在群里)— 30 天 TTL
2. DM 级偏好(@bot model X 在 DM)— 30 天 TTL
3. 管理员默认(模型目录的 default_model,在 Web 的「更多 → 管理 → 模型」里设;没改过时是 Kimi K3)
4. 兜底:模型目录读不到时用内置目录,它的默认同样是 Kimi K3
```

要永久切换全部群的默认 → 让管理员在 Web 的「更多 → 管理 → 模型」里改默认模型。保存后 IM 侧最多约 1 分钟生效,**不用重部**。

### 15.5 对话对象:`agent` 决定这个会话由谁来答

和 Web 端「新对话」上那一排对话对象(§1.4)是**同一个概念**:IM 端一共两个对象,任何用户都能随时切,**默认是第一个**。

| 对话对象 | 命令 | 谁在答 | NotiOps 侧 token |
|---|---|---|---|
| **AWS DevOps Agent** | `agent devops`(默认) | 你自己 AWS 账号里的 DevOps Agent,直连 | **0** |
| **NotiOps Agent** | `agent notiops` | 我们的 AgentCore runtime,挂只读工具 | **会消耗**(用 §15.1 选的模型) |

```
@bot agent              # 看这个会话现在由谁答(查看永远不改任何东西)
@bot agent notiops      # 切到走模型的 NotiOps Agent
@bot agent devops       # 切回 AWS DevOps Agent 直连(默认)
@bot agent default      # 清除偏好,回到默认(AWS DevOps Agent)
```

- 中文说法一样认:`/智能体 notiops`、「智能体 devops」。这条是**确定性路由,0 token** —— 切换本身不花钱。
- **范围与生效层级和 `model` 逐字相同**:在**群里**发 → 整个群之后都用这个对象(包括别人的提问);在**私聊**发 → 只影响你的 DM。偏好 **30 天 TTL**,一个群半个月不说话就回到默认。飞书 / Slack / 钉钉三家**各自独立记**(见 §17.3)。
- 打 `/help` 能看到这一行(`/agent notiops|devops`)。
- **切换对象不带历史**:两条路根本不是同一个上游,切过去前面聊的内容不会搬过来。想接着上一轮问,先切回去。
- **`model` / `web` 只对 NotiOps Agent 那条路有意义**:DevOps Agent 直连不经我们的 Bedrock 模型,你照样可以发 `model`,它改的是 NotiOps Agent 那条路。
- **`investigate` / `case` / 定时日报**一个都**不受影响**。`agent` 只管"自由提问那一句交给谁"。

## 16. 语言偏好(中 / 英切换)

### 16.1 三种触发方式

```
language        # 查看当前语言 + 简短帮助
language zh     # 切到中文(立即生效,90 天偏好)
language en     # 切到英文(立即生效)

请帮我切换到英文     # 自然语切换,等价 language en
切换到英文          # 同上
请用英文回复         # 同上
switch to chinese   # 等价 language zh
```

### 16.2 语言优先级链

bot 决定每条消息回什么语言时,**按这个顺序找答案**:

```
1. 你的显式偏好(language zh|en 或自然语切换设置过)
2. 当前调查锁(派发后,整轮调查锁定一种语言)
3. 当前 thread 锁(群里某条 @bot 之后开的话题)
4. 当前 DM 锁(私聊第一条消息检测后锁定)
5. 自动检测当前消息语言
6. 群组 / 工作区默认语言(管理员配置)
7. 兜底:英文
```

为什么这么复杂? 因为:
- 你不想群里跟同事讨论技术问题时, 一条 `why?` 突然把所有人切到英文
- 你不想刚切到英文,下次发"你好"又被检测成中文
- 你的偏好应该跨群、跨设备稳定

### 16.3 常见困惑

**问题**:我刚 `language zh`,但下条 bot 还是英文?

**原因**:可能是这条消息恰好在某个 thread 里,thread lock 优先级高于 user pref 之外的所有层。

**解决**:**user pref 是最高层**,会盖过所有 lock。如果 `language zh` 写入失败(管理员看 worker 日志 `/aws/lambda/notiops-im-worker-<平台>`,一键部署是 `/aws/lambda/<栈名>-im-worker-<平台>`),让管理员清下你的 `locale#user#<uid>` row。

## 17. 钉钉(DingTalk)平台特别说明

钉钉与飞书 / Slack 走**同一套 Lambda webhook 形态**,意图集也完全一致 —— 没有"钉钉少一半功能"这回事。剩下的差异是钉钉 IM 协议本身的**永久性**能力限制(消息发出去改不了、卡片按钮没有回调),不是交付排期。本节说清楚哪些一致、哪些形态不同。

### 17.1 与飞书 / Slack 一致的能力

| 功能 | 钉钉可用 |
|---|---|
| @ bot 触发(群)/ DM 直发 | ✅ |
| 深度调查派发(`/调查 i-xxx CPU 高` / `深入排查 RDS my-db 慢查询` 等,见 §13.4) | ✅ |
| 概念问答(`什么是 EKS` / `ALB 和 NLB 的区别`) | ✅ |
| 模型切换(`@bot model claude/kimi/gpt`) | ✅ |
| 对话对象切换(`@bot agent notiops/devops`) | ✅(三家逐字同一套实现,见 §15.5)|
| 语言切换(`language zh/en` / 自然语) | ✅ |
| AWS Support case 创建 / 列表 / 查看 / 回复 / 关闭 / 分析 | ✅ |
| 调查报告 markdown 回贴 | ✅(由应用机器人回贴到**发起调查的那个会话**,不需要额外配置)|
| 主动推送(每日运维通知 / 实时告警 / 巡检推送) | ❌ 本版本钉钉一样都收不到:每日运维通知只发飞书;实时告警推送哪个平台都没接上(§14);巡检推送是唯一会投钉钉的一种(发送地址是群里另加的自定义机器人,即 secret 里的 `webhook_url`),但还要先把群登记成推送目标,而这一步本版本**还没有**途径(没有网页入口、`setup.sh` 不问、发布包里也没有对应的工具)。对话与调查派发不受影响 |
| 进度反馈 | 部分:普通问答的进度是追加式的;深度调查**不自动刷新**(中间进展点回执里的链接去 DevOps Agent 后台看),见 §17.2 |
| 零变更承诺(任何变更类请求都拒绝;默认由 DevOps Agent 侧 + 只读角色保证,`/agent notiops` 时由 NotiOps AgentCore Runtime 的只读角色 + 只读工具保证,两条路上都有 NotiOps 侧正则二道门;唯一的写是你确认后才执行的 Support case,见 §9) | ✅ |

> 📌 **Skill(自建能力包)不在这张表里**:2026-09-06 起 skill 相关意图已从 **IM 侧整体退役** —— 飞书 / Slack / 钉钉三家都不再提供 skill 选择 / 切换 / 上传。完整的 Skills 能力在 Web Chat 端,见 §5。

### 17.2 钉钉端的形态差异(永久,不是排期问题)

钉钉的 IM 协议跟飞书 / Slack 有几个不可绕过的差异。这些差异不会随版本消失,能力本身都在,只是长得不一样:

- **进度是追加式的,不是原地刷新的卡**:钉钉**已发出的消息改不了**,做不到飞书 / Slack 那种同一张卡原地刷新。普通问答的进度作为**新消息追加**在会话里,节流方向也因此**反过来收紧** —— 一轮最多追加 2 条(大约在 120s / 360s),免得每次进度都把整个群顶一次未读;进度照样送达,只是往下滚,而不是原地变。**深度调查则不追加任何进度**:回执里会明说「这条不会自动更新」,中间进展点回执里的链接去 DevOps Agent 后台看,报告跑完自动投回这个会话。
- **没有 Next-step 一键派发按钮**:钉钉卡片的按钮只能跳 URL,**没有"按钮 → 回调服务器"这条通道**,所以报告末尾的下一步建议在钉钉端只能以**文本条目**呈现,你照着再发一句话即可。这是钉钉平台的能力限制,飞书 / Slack 的一键按钮在钉钉端不可能有。
- **没有原生 modal 表单 → 开案例走可复制的纯文本模版**:飞书 / Slack 的"打开 case 表单填字段"在钉钉无等价物。钉钉端你说一句「开案例」,bot 直接回**一张六行纯文本模版**(问题描述 / 严重等级 / 语言 / 案例类型 / 涉及服务 / 标题,上下各夹一条分割线,每行都写好了默认值和可选项)。你**整段复制、改完发回来**即可 —— 只有「问题描述」必填,其余保持默认也能建;bot 解析后出确认卡,你再回一句「**确认**」才真的建案例。分割线会被自动剥掉,不会进案例正文。
- **危险动作靠回一句「确认」而不是点按钮**:同上,关闭案例这类写操作在钉钉端也是"回「确认」"二次确认。
- **巡检推送最多一个目标**:钉钉上会投的主动推送只有巡检推送一种(本版本还配不起来,见 §17.1),而它的发送地址绑死自定义机器人所在的那个群,所以最多只能有**一个**启用的推送目标;飞书 / Slack 可以有多个。
- **不渲染 markdown 表格**:钉钉按标准 markdown 解析,但**不认表格**,所以报告里的表格会被统一降级成可读的文本行。
- **没有 thread 子话题语义**:钉钉群里没有 Slack `thread_ts` 那种"在某条消息下开 thread",唯一可用的作用域就是整个群。所以自动语言锁在钉钉端**只在单聊里生效**(锁 30 天);群里每条消息各自判断语言 —— 否则一个人问一句英文就会把整个群翻成英文。想把语言钉死就用 `language zh/en`(见 §16),显式偏好优先级更高。
- **每条 @ bot 消息都是给 bot 的**:钉钉机器人**默认收不到群里非 @ 自己的普通聊天**,所以 bot 不需要"判断是不是 @ 我了"——只要消息进来就是给它的。简化了交互,但也意味着无法做"thread 内追问免 @"(飞书 / Slack 有的)。

### 17.3 切换平台不丢偏好

`@bot model` 和 `language` 偏好按 `(平台, 群 ID)` / `(平台, user ID)` 隔离记录,**飞书的偏好不会带到钉钉,反之亦然**。同一个用户在飞书 DM 用 Claude,在钉钉群用 Grok,各自独立。

## 19. 常见疑问 FAQ

### Q1: 我能让 bot 帮我重启某个 EC2 吗?

**不能**。bot 对你的基础设施是 read-only(唯一的写是你确认后才执行的 AWS Support case),产品级硬规则,不可绕过 —— 默认由 AWS DevOps Agent 侧 + 它使用的
IAM 角色(对你的基础设施只读)保证;`/agent notiops` 时由 NotiOps AgentCore Runtime 的只读角色和只读工具保证;
两条路上 NotiOps 侧都再加一条正则二道门(见 §9)。详见
[TECHNICAL_DESIGN.md §5 安全设计](TECHNICAL_DESIGN.md#5-安全设计)。

变通:**问 bot 怎么重启**(教程式),它会教你 CLI 命令,你 review 后自己执行。

### Q2: bot 怎么会知道我的 AWS 资源?

bot 自己**不去读**你的 CloudWatch / EC2 / RDS 这类资源。默认它把问题和调查都交给你自己的 **AWS DevOps Agent**,Agent 用客户授权给它的角色读你的资源;对话对象切到 `/agent notiops`(§15.5)之后,自由提问改由 NotiOps 的 AgentCore Runtime 用它的只读角色去读(与 Web Chat 是同一个 runtime,见 §8.1)。

bot 的 Lambda 角色能做的事**不止**「发消息」,包括:

- 收发 IM 消息(平台凭据存在 Secrets Manager 里);
- 发起 DevOps Agent 深度调查、读调查进度,以及直连 DevOps Agent 对话;
- 调 NotiOps 的 AgentCore Runtime(`/agent notiops` 那条路);
- 调 Bedrock 模型(案例智能分析、建案时自动判断服务);
- **开 / 回复 / 关闭 AWS Support case**(你在卡片 / 表单上确认、或在钉钉上回「确认」之后才执行);
- AssumeRole 进已接入成员账号里 NotiOps 的触发角色和采集角色(跨账号派调查、跨账号开案例要用);
- 读写 NotiOps 自己的 DynamoDB 表,以及数据桶里的报告和 Skills。

### Q3: 我的聊天数据存多久?

| 类型 | TTL |
|---|---|
| 聊天事件 / 调查上下文 | 7 天 |
| 调查报告 HTML(S3) | **不会自动删除**:`investigations/` 前缀没有生命周期规则,对象一直留在数据桶里,直到桶被删除。卡片上的链接指向 `reports/` 下的一份副本(约 7 天后随生命周期删除,链接随之失效);没配报告 CDN 时链接是预签名 URL(数小时内有效,最长约 12 小时) |
| 语言偏好 | 90 天 |
| DM 锁 | 30 天 |
| 群 thread 锁 | 7 天 |
| 调查锁 | 24 小时 |
| Push 事件去重 | 5 分钟 |

除调查报告外,都由 DDB TTL 自动清理,不需要人工干预。

### Q4: bot 突然不响应了,怎么办?

按 §20 流程让管理员排查。常见原因:
- IM 凭据过期或被改(管理员在 Web Chat「更多 → 管理 → 集成 IM」里重新录入,或者直接改 Secrets Manager 里那个 Secret)
- Bedrock 限流(高峰期偶尔;只影响走模型的那几处 —— `/agent notiops` 的问答、案例智能分析)
- 回的是「上一个问题在 NotiOps Agent 那边还没跑完」:`/agent notiops` 下上一个问题还在 agent 那边算,这一条没有发出去。等几分钟再问;急的话先用 `/agent devops` 走 DevOps Agent 直连。
- 回答末尾标着「回答在中途断了」:上面的内容不完整,再问一次;反复断在同一处就发 `/model` 换一个模型。
- 回复说「模型的输出连续两次崩成了乱码」:`/agent notiops` 下模型的输出崩成了乱码,系统已经自动重试过一次、又崩了(乱码不会留在卡片上)。发 `/model` 换一个模型再问。

### Q5: 我能不能把 bot 加到非生产群?

可以,**强烈推荐先在测试群试用 1-2 周**。bot 默认对拉它进去的所有群都回答,管理员可以用群允许清单收窄:一键部署是栈参数 `ImAllowedChatIds`(参数页上叫 **IM chat/channel allow list**,见 [DEPLOYMENT_ONECLICK.md](DEPLOYMENT_ONECLICK.md));`setup.sh` 部署是在 `infra/cdk.json` 的 `context` 里加 `imAllowedChatIds`,再重跑 `./setup.sh`(见 [DEPLOYMENT.md §8.1](DEPLOYMENT.md))。

### Q6: bot 回的内容是模型生成的吗?会不会胡编?

- **调查报告**:DevOps Agent 真实读你的资源生成,有 trace.html 可查,不会编
- **概念问答**:默认由你自己的 DevOps Agent 直连回答(NotiOps 侧 0 token,不带来源块);对话对象切到 NotiOps Agent(`@bot agent notiops`,见 §15.5)后,才是 Bedrock 上的对话模型(默认 Kimi K3)+ AWS 官方文档检索(Knowledge MCP),回答带「参考来源」里的 URL,可点击验证(见 §13.2)
- **意图判断**:确定性规则匹配,不调模型(0 token),规则见 §13.4
- **调查进度**:进度卡上逐条贴的是 DevOps Agent 自己调查日志里的新条目,NotiOps 不调模型、不另写叙事(§11.3)

如果 bot 给的概念回答跟你认知不符,**点「参考来源」里的 URL 自己看 AWS 官方文档**(DevOps Agent 直连的回答不带来源块,就直接去 AWS 官方文档里查)——这是 ground truth。

### Q7: AWS Support case 创建到 bot 这边会扣 Support 费吗?

不会,bot 只是调用你账号已有的 AWS Support API。case 本身不另外计费(Support plan 内的 case 数量都包含)。

### Q8: bot 在调查时,DevOps Agent 会不会跑出"非预期的"操作?

DevOps Agent 是 read-only 设计(用客户授权的角色,该角色应该只挂 ReadOnly policy)。bot 派发时也只传调查请求文本,**不传任何 mutating 指令**。

但**前提是**:你给 DevOps Agent 的 role 没有意外授予了写权限。建议运维定期 audit 这个 role。

## 20. 反馈与求助

### 20.1 反馈渠道

想提需求或报问题:到公开仓库的 Issues 页提一个 issue(Web Chat 左下角、你名字右边那个 GitHub 图标打开的就是仓库首页,见 §1.2),或者直接告诉部署这套 NotiOps 的管理员。

⚠️ **别在群里 @ bot 说「我希望你能…」来提反馈** —— 那句话不会被记下来:它会被当成一个普通问题,转给这个群的对话对象去答(默认是你自己的 DevOps Agent);bot 的日志只记错误类型这类元数据、不记消息原文,所以管理员在日志里也看不到它。

### 20.2 求助路径

| 问题 | 找谁 |
|---|---|
| bot 没回我 | 内部群管理员 / IT 运维 |
| bot 回了但内容明显错 | 截图发给管理员;管理员看 worker 日志 `/aws/lambda/notiops-im-worker-<平台>`(一键部署是 `/aws/lambda/<栈名>-im-worker-<平台>`)—— 那里只有错误类型这类元数据,没有消息原文,所以截图要带上你的原话 |
| 调查报告打不开 | 多半是链接过期了:卡片上的链接约 7 天内有效;卡片底下那行写的是「数小时内有效(最长约 12 小时)」时,说明这套部署没配报告 CDN、用的是 S3 预签名 URL,几小时后就会失效。报告还在桶里,但链接不会续期 —— 要再看这次调查,点进度卡上的「🔬 查看本次调查」(钉钉是回执里的链接)去 DevOps Agent 后台看,需要登录控制台(见 §11.4) |
| 我没权限调查这个资源 | 这是替你作答的那一方的角色权限问题(默认是你的 DevOps Agent 用的角色;`/agent notiops` 时是 NotiOps AgentCore Runtime 的只读角色),不是 bot 的问题 |
| AWS Support case 创建失败 | 看 bot 返回的错误,大概率是 Support plan 限制或 severity 不允许 |
