# Cost & Usage Analysis (for a given time window)

When the user asks to "analyze cost/usage for a period", "how much did we spend", or "do a cost analysis and give recommendations", run a **structured, actionable** cost analysis per this skill.

## Step 1 — Confirm the time window
- Parse the time window from the user's request. When they say relative phrases ("last month", "this month", "last week", "Q2"), **convert to absolute start/end dates (YYYY-MM-DD) using the current date**, and state the exact range at the top of your reply to avoid ambiguity.
- If no window is given → default to "last 30 days", but note the user can specify another range.

## Step 2 — Gather data (use FinOps tools, all read-only)
Call cost tools as needed to cover these dimensions (not all are mandatory — focus on the user's question, but a "detailed analysis" should be as complete as possible):
1. **Overview**: total cost in the window, daily average, and change vs. the previous equal-length period (up/down amount + percentage).
2. **By service**: top spending services (at least top 5–10), each with amount and share.
3. **By usage dimension**: usage drivers of the major services (e.g. EC2 instance-hours/types, S3 storage/requests, data transfer GB).
4. **Anomalies & trends**: any cost anomalies, spiking services or usage types.
5. **Optimization opportunities**: idle/underused resources, RI/Savings Plans coverage & utilization, rightsizing recommendations, Cost Optimization Hub recommendations (if available).

> Data source priority: use Cost Explorer when aggregate data suffices; use CUR/Athena when you need resource-level/detailed dimensions (e.g. drill down by instance or usage type). If a data source is unavailable (e.g. CUR not ready), say so honestly and proceed with what's available — never fabricate numbers.

## Step 3 — Output (decision-oriented, not raw data dumps)
Structure the reply as:
1. **One-line conclusion**: window, total spend, MoM trend (e.g. "Jul 1–31 total cost $X, +12% vs. June, driven mainly by EC2 and data transfer").
2. **Cost breakdown**: top-services table (service / amount / share / MoM).
3. **Notable points**: anomalies, spikes, obvious waste (each with dollar impact).
4. **Recommendations**: 3–5 concrete, executable actions ordered by **estimated savings (descending)** (e.g. "3 idle RDS instances ~$X/mo, stop/downsize"; "SP coverage only 40%, buying a 1yr Compute SP saves ~$Y/mo"). For each: **what to do + estimated impact + risk**.
5. If data is incomplete, clearly note which dimensions are missing and why.

## Principles
- **Read-only**: analyze only, never modify resources. Give recommendations; the user decides whether to act.
- **Numbers must come from tool results** — never invent cost/savings figures. State currency (USD).
- Be concise, lead with conclusions, use tables; don't paste raw tool JSON.
- Reply in the user's language (Chinese for Chinese users, English otherwise).
